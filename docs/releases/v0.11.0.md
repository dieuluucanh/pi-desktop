# Pi Desktop v0.11.0

**Release date:** 2026-11-19 · **Status:** published to GitHub Releases by
`.github/workflows/release.yml` on tag `v0.11.0` · **Pi SDK:**
`@earendil-works/pi-coding-agent` 1.5.0 · **Companion extension:**
`@dieulc/workflow` ≥ 0.12.0 · **Bundled runtime:** Node 24.22.2

Pi Desktop is a standalone desktop app for the [Pi coding agent](https://pi.dev):
projects, sessions, chat, providers, models, extensions, packages, skills, themes and
settings in a UI, using the **same `~/.pi/agent` profile as terminal Pi**, so the two are
interchangeable. **Pi for Office is an optional integration**, not a built-in surface.

This is the tenth public release, a **workflow-parity** release on top of v0.10.1. An
extension prompt now owns the keyboard even when focus stayed on the page, and the
folder-policy title keeps the `Outside:`/command lines the extension wrote. Review Mode
paints one extension-owned line where terminal Pi paints it, the Workflow todo panel gets
native controls in every mode, and the terminal page-scrolls an alternate screen instead
of turning the wheel into prompt history. Web tabs honour a page's own close and return to
the session that opened them, the bell's app offers are derived from live state instead of
a stored archive row, and the sidebar's Projects header stays pinned above a long list.

## Highlights

- **An extension dialog owns the keyboard.** The dock listens on the window while its
  pane is active, so arrows, `j`/`k`, Enter, Escape and Ctrl+C work even when focus is on
  `document.body`; the select title renders with its real newlines, and app shortcuts no
  longer fire underneath the prompt.
- **One Review line, in terminal Pi's place.** The row below the todo panel and above the
  composer carries the extension's `workflow-review` text — running/paused/handoff hints
  included — plus the desktop-only Pause/Resume/Abort controls. The generic working row
  and the footer's duplicate status are suppressed.
- **The todo panel has native controls.** A bar above the panel shows progress and state
  and dispatches the extension's `/todos` verbs (Automatic, expand, collapse, hide) in
  Plan, Build, Review and Default. It survives Hide, so the choice is always reversible.
- **The wheel scrolls, paste arrives.** An alternate-screen TUI gets PageUp/PageDown per
  wheel gesture instead of synthesized arrows. Ctrl/Cmd+V, Shift+Insert, the right-click
  menu and Edit ▸ Paste deliver one bracketed paste into the questionnaire's own editor.
- **A closed web tab returns to its opener.** A page's `window.close()` is a close
  request, closing a session cascades to its linked review tabs, and a reused review URL
  re-points its link to the latest session.
- **Notifications are state, not a cache.** App and extension updates are derived from
  live updater/package state; `×`/Clear persist a dismissal, and **Notify me again** brings
  the offer back.
- **The Projects header stays put.** The sidebar's first row is structurally outside the
  scroller, so a long project list no longer carries it away.

## What changed since v0.10.1

### Extension dialogs take the keys wherever focus is

The folder-policy prompt is `ctx.ui.select` with a multi-line title. Two defects made it
diverge from terminal Pi: the title was rendered raw inside an `<h2>` (HTML collapsed the
`Outside:` line and every `  • command` bullet into one paragraph), and Up/Down, `j`/`k`,
Enter and Escape were attached to the listbox or the dock root — a prompt whose focus
stayed on `document.body` ignored them, and Escape could fall through to the app and stop
the run.

`src/renderer/src/extension-ui/dialog-keys.ts` is now the pure policy: `tui.select.*`
comes from the profile's `keybindings.json` (with Pi's defaults until the snapshot
arrives), `j`/`k` move like arrow keys, movement clamps at the ends instead of wrapping,
Enter selects the highlighted option, and Escape/Ctrl+C cancel. Input/editor dialogs keep
normal typing, gain the focus-independent Escape, and deliberately keep Ctrl+C as copy
instead of Pi's cancel. Confirm dialogs move focus between Confirm/Cancel and require a
focused button for Enter, so a lost-focus Enter can never answer a permission. Every
response path settles once, so a double Enter or an Enter+click sends one `oi.respond`.

The title renders through `MultilineText` with tabs normalised to three spaces and a
height-capped scroll region, so long command lists stay readable. `SessionView` passes
`active` for the focused pane only, and `ShortcutDispatcher` blocks app shortcuts and
`app.interrupt` while a dialog owns the active tab; `Ctrl+O` remains available because
terminal Pi's selector supports it. Coverage is `tests/renderer/dialog-keys.test.ts`,
`tests/renderer/extension-ui.test.tsx`, `tests/renderer/shortcut-dispatcher.test.tsx` and
the real-Electron `tests/e2e/extension-dialog.spec.ts`.

### One Review line below the todo panel

Review used to paint two stacked rows above the todo widget, and neither matched terminal
Pi: `ReviewBar` printed its own `Review owns the turn · modes locked` text while the
generic working row repeated the command hints. `src/shared/workflow-mode.ts` now carries
the canonical phase fragments and `reviewLineText()`: it prefers the extension's
`workflow-review` status with its ANSI intact, completes a line that omits its command
hints, and falls back to the canonical phase line when an older extension publishes
nothing.

`ReviewBar` renders that line and keeps Pause/Resume/Abort (or **Open review tab** during
the handoff) fixed on the right. `SessionView` places the row after the above-editor
widget strips and before the composer, suppresses `WorkingRow` while the line owns the
turn, and `SessionFooter` omits the promoted `workflow-review` key so the text appears
once. The extension half ships in `@dieulc/workflow` 0.13.0; until that version is
installed the desktop shows its canonical line — commands and phase are present, the
extension's live pass/finding detail is not.

### The Workflow todo panel has native controls

The panel itself remains the extension's read-only `workflow-todos` widget. A widget frame
now carries its `setWidget` key as `TuiFrame.key`, which `src/shared/workflow-todos.ts`
uses to identify the panel and decode progress/state from the frame, the string widget,
the compact `workflow-todos` status or the existing `workflow` progress; an unknown shape
degrades to “no panel” instead of guessing from glyphs.

`TodoPanelBar` mounts above the above-editor strips in Plan, Build, Review and Default and
stays visible when the list is hidden. It shows `Todos done/total`, the effective state and
settled/stale markers, with an Expand/Collapse toggle and a menu for Automatic / Show full
list / Collapse / Hide. Actions dispatch `/todos auto|expand|collapse|hide` through
`commands.run` — never a prompt — so they work in Review and behind a TUI overlay, with
focus restored to the surface or composer afterwards. The View menu has a **Todo Panel**
submenu, the palette has a Todo panel group, and `todos.toggle` binds to `Ctrl+Alt+L`
(`Ctrl+Alt+O` remains Sessions). The footer omits the promoted `workflow-todos` status.
With a 0.12.x extension the bar is absent while the list is hidden or Review owns the
turn (the desktop has no compact status to read); the menu and palette still dispatch the
command.

### Wheel paging and paste for terminal and extension frames

**The wheel no longer becomes prompt history.** xterm's alternate-screen fallback writes
`ESC[A`/`ESC[B` to the PTY when the running program reports no wheel, which inside the Pi
TUI recalled previous prompts. `src/shared/terminal-wheel.ts` takes exactly that state
over: one PageUp/PageDown per gesture (a same-direction burst within 180 ms is one gesture),
a swallow for a zoom chord or a horizontal wheel, native scrollback on the normal screen,
and xterm's own SGR path when the program reports the wheel (`mouseTrackingMode` is
`vt200`/`drag`/`any`). No arrow is ever synthesized, and `TerminalView` restores a
pass-through handler on unmount because the pooled xterm outlives the view.

**Paste reaches the questionnaire.** Its answer field is the extension's own pi-tui
component, not a DOM input, so Chromium's paste command never ran on it: Ctrl+V arrived as
the raw byte `\x16`, Cmd+V was dropped, and `webContents.paste()` is a no-op on a
non-editable `div`. The surface now recognises Ctrl+V, Ctrl+Shift+V, Cmd+V and
Shift+Insert, reads the clipboard, and sends **one bracketed paste**; the `paste` event
path (middle-click, a menu paste) goes through the same `createPasteIntake` decision point,
so one gesture writes once and two deliberate pastes both pass. Paste delimiters in the
body are stripped. The surface reports keyboard ownership (`IPC.tuiFocus`), so the
right-click **Paste** and **Edit ▸ Paste** route to that frame; with no extension frame
focused, Edit ▸ Paste remains the native command. The extension keeps its own input/editor
semantics (newline stripping, line-ending normalisation, its own `[paste #N]` marker).
Image and file paste still have no path into an extension frame.

### Web tabs close and return to their opener

A `WebContentsView` has no window, so Plannotator's completion overlay could call
`window.close()` without removing the desktop tab. The adapter now installs a
`window.close` interceptor at `dom-ready` through `executeJavaScript`, with a
`webContents` `destroyed` listener as the fallback for a page that saved the native
reference; both surface as one `close-requested` event and main closes the tab through the
session service. The interceptor adds no preload, Node surface or bridge channel, so the
partition stays preload-free and sandboxed.

`src/main/tab-selection.ts` is the pure close policy: a closed web tab returns to its
linked `sessionTabId` when that tab is still open, otherwise to the most recently active
remaining tab, with `createdAt` descending and id ascending as deterministic tie-breaks.
Closing a session cascades to its linked review tabs in the same publish, and a reused
review URL re-points the link to the latest opener. A manual **Open URL in Tab…** stays
unlinked and falls back to MRU. Up to six `WebContentsView`s stay live (active plus
recent/visible); an evicted view reloads on activation.

### Notification offers are derived from state

The bell now composes two channels. The archive holds extension `ctx.ui.notify` events,
bounded at 100 rows. App-owned **offers** — a release and an extension update set — are
state, not arrivals: the renderer derives them from live updater/package state through
`offerNotifications`, so a row exists exactly while its condition holds and an applied
update clears it without bookkeeping.

An app offer follows the updater phase (available / downloading / ready to install) and
one row per offered version; an extension offer is one per update set and narrows to the
remaining count after a partial update. `dismissedVersion` and `dismissedSignature` record
an offer removed with `×` or **Clear**, and **Notify me again** in About & updates or the
Packages card clears the marker. `notifiedVersion`/`notifiedSignature` now gate toasts
only, per-message mute rules apply to archive rows only, and the sidebar dot shares
`isUpdateOfferPhase`. A new version or a changed set no longer matches its dismissal and
raises the row again.

### The sidebar's Projects header stays pinned

The Projects label, the `+` menu (default · new · clone), **Open project folder** and
**Hide sidebar** used to live inside the only `ScrollArea`, so a long project list
scrolled them away. `projects/ProjectsHeader` is now a sibling **before** the scroller in
`layout/Sidebar.tsx` — a structural pin like the panel rail's header, not
`position: sticky`, so no opaque repaint, `z-index` or fixed sticky offset is involved.
The wrapper's `px-3` folds the old `nav px-2` plus section `px-1`, and the row's own
`px-2` keeps the 20 px inset. `tests/e2e/shell.spec.ts` scrolls a 30-project list and
asserts the header does not move.

## Install

Download from [GitHub Releases](https://github.com/dieuluucanh/pi-desktop/releases).

| Platform      | Artefacts                                                                                                              | Status  |
| ------------- | ---------------------------------------------------------------------------------------------------------------------- | ------- |
| Windows (x64) | `Pi-Desktop-0.11.0-win-x64-setup.exe` (NSIS), `Pi-Desktop-0.11.0-win-x64-portable.exe`                                 | primary |
| Linux         | `Pi-Desktop-0.11.0-linux-x86_64-appimage.AppImage`, `Pi-Desktop-0.11.0-linux-amd64-deb.deb` (x64) and the `arm64` pair | beta    |
| macOS         | `Pi-Desktop-0.11.0-mac-arm64.dmg`, `Pi-Desktop-0.11.0-mac-x64.dmg` (plus the `.zip` pair used by the updater)          | beta    |

Builds are **unsigned**. Windows SmartScreen warns on first launch (**More info → Run
anyway**). macOS additionally requires an explicit approval:

1. Open the `.dmg` and drag **Pi Desktop** into `/Applications`.
2. Launch it once. macOS refuses, and there is no right-click override any more.
3. Open **System Settings → Privacy & Security**, scroll to the bottom, and choose
   **Open Anyway** for Pi Desktop.

If the bundle reports that it is **damaged** instead (usually after unzipping the `.zip`
rather than mounting the `.dmg`), clear the quarantine flag and try again:

```bash
xattr -dr com.apple.quarantine "/Applications/Pi Desktop.app"
```

On Linux, the AppImage needs FUSE (`libfuse2`, or run with `--appimage-extract-and-run`);
install the `.deb` with `sudo apt install ./…deb` rather than `dpkg -i` so the
GTK/NSS/asound dependencies resolve. The app bundles its own Node runtime: no system
Node, npm or Pi install is needed.

| Linux (AppImage) | yes                    | yes                                        |
| macOS            | **no**                 | **no** — download the new `.dmg`           |

macOS updates stay download-only: Squirrel.Mac validates a downloaded update against the
running app's code-signing requirement, and an ad-hoc signature's requirement changes with
every build. **About & updates** says **Manual updates** and links to the Releases page.

v0.11.0 is the version an installed v0.10.1 build picks up (Windows and the Linux
AppImage). macOS stays manual.

## Known limitations in v0.11.0

Every known limitation is recorded here and in the user guide:

- **Unsigned builds** — SmartScreen/Gatekeeper warn on first launch; signing is deferred
  ([backlog](../product/backlog.md)).
- **macOS and Linux are beta** — built and structurally verified in CI, but no real macOS
  launch and no fresh Linux desktop install have been exercised by a person for this
  release. Windows is the verified target.
- **The live Review line needs the matching extension** — the desktop prefers the
  extension's `workflow-review` text, but `@dieulc/workflow` 0.13.0 (which publishes it and
  the hidden-panel `workflow-todos` status) is a separate package. With 0.12.x the row
  falls back to the canonical phase line, and the todo bar is absent while the list is
  hidden or Review owns the turn (there is no compact status to read); commands and
  controls keep working.
- **Extension dialogs diverge from terminal Pi in two deliberate places** — Ctrl+C in an
  input/editor stays copy rather than cancel, and confirm needs a focused button for Enter
  rather than answering the highlighted “Yes”. Both protect a desktop text field or a
  permission prompt from a stray key.
- **Dialog keys are not exercised against the real folder policy in automation** — the
  E2E uses the exact `ctx.ui.select` shape, but the manual multi-command walkthrough with
  the external workflow extension and terminal Pi side by side was not run for this
  release.
- **The wheel policy is a gesture heuristic** — a same-direction burst within 180 ms is one
  PageUp/PageDown, and a zoom chord or horizontal wheel is swallowed. A trackpad that emits
  slower events pages more than once; the normal screen and programs that report the wheel
  keep xterm's own behaviour.
- **Paste into an extension frame is text only** — image and file paste still have no path
  there; use the native composer for attachments. A page or extension that expects a DOM
  paste event will not see one.
- **A page can still bypass the close interceptor** — a page that saved a native
  `window.close` reference is handled by the `destroyed` fallback, but a page that keeps
  the view alive without closing it at all cannot be detected. The tab outcome is still
  correct for both supported paths.
- **A closed review tab can collapse a split grid** — returning to the linked session
  selects it; if no visible pane holds it, the existing solo-surface rule applies. This is
  the normal strip-tab rule, not web-tab specific.
- **App offers are in-app only** — the bell row, its toast and the sidebar dot are the
  whole surface; there is no OS notification. A dismissed offer stays dismissed until the
  version/set changes or **Notify me again** is used, and per-message mute rules never
  apply to offers.
- **Extension update checks are registry-based** — they need the network, pause under
  `PI_OFFLINE`, and can lag a fresh publish by a few seconds. A pinned package is skipped
  by design, and a Git or ranged source has no single target version to name.
- **An updated package takes effect on the next session** — a running session keeps the
  code it loaded until **Reload runtime** (or a restart).
- **The bundled Pi agent is not user-updatable** — it moves with Pi Desktop. This release
  pins `@earendil-works/pi-coding-agent` 1.5.0; a stale agent is a release-pipeline warning
  by default, not a blocked tag, and a major is never taken automatically.
- **Prompt-history measurement needs a measurable line box** — the composer's `text-sm`
  keeps a numeric line height. A hidden composer, `line-height: normal` or a browser without
  `Range` geometry falls back to the logical-line gate; the session E2E test fails if that
  style contract breaks.
- **Transcript find cannot mark across a soft break** — a query spanning a line break is
  counted by the matcher but one `<mark>` cannot span the rendered `<br>`; copy still uses
  the raw message text.
- **Informational notifications are hidden in the bell by default** — that switch scopes
  to the bell and toasts only; the transcript always shows the text. Hidden bell rows are
  never lost: **Show hidden (N)** reveals them.
- **Upstream** SDK/provider changes can affect extensions and model behaviour; this
  release pins `@earendil-works/pi-coding-agent` 1.5.0 and requires the companion workflow
  extension 0.12.0 or newer for Review Mode, with 0.13.0 for the shared review line and
  plan-scoped todo choice. Pi's own `settings.json` and session-JSONL writes are not
  crash-atomic; the app's own profile writes are (`fsync` + rename).
- **Verified structurally, not on a live machine** — the Linux and macOS artefacts are
  built and structurally checked in CI; no person has launched every artefact on real
  hardware for this release. Review Mode's manual provider matrix, the cross-version todo
  matrix and the Plannotator auto-close matrix were not re-walked for this build.
- **The terminal is local only** — one shell per tab, no SSH/remote session, no tmux
  control mode and no docked split panel; it does not spawn in an untrusted project until
  you grant trust. The Linux native backend is built for **glibc 2.31 /
  `GLIBCXX_3.4.28`**.
- **Deferred features** are listed in [`../product/backlog.md`](../product/backlog.md).
