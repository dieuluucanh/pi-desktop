# Pi Desktop v0.10.1

**Release date:** 2026-11-15 · **Status:** published to GitHub Releases by
`.github/workflows/release.yml` on tag `v0.10.1` · **Pi SDK:**
`@earendil-works/pi-coding-agent` 1.5.0 · **Companion extension:**
`@dieulc/workflow` ≥ 0.12.0 · **Bundled runtime:** Node 24.22.2

Pi Desktop is a standalone desktop app for the [Pi coding agent](https://pi.dev):
projects, sessions, chat, providers, models, extensions, packages, skills, themes and
settings in a UI, using the **same `~/.pi/agent` profile as terminal Pi**, so the two are
interchangeable. **Pi for Office is an optional integration**, not a built-in surface.

This is the ninth public release, a **composer-navigation** patch on top of v0.10.0. `↑` and `↓` now walk
prompt history only at the buffer's **displayed** rows, so a long paragraph that
soft-wraps keeps the browser's native caret movement until the caret reaches the real top
or bottom row. Only a plain arrow with a collapsed caret touches history: `Shift+↑` /
`Ctrl+↑` keep their native selection and word movement, and `Alt+↑` stays the dequeue
chord. A real-Chromium E2E test proves the wrapped layout, and the Windows splitter E2E no
longer depends on a synthetic pointer drag.

## Highlights

- **History follows displayed rows.** `↑` recalls the previous prompt only from the first
  displayed row, soft wrap included; `↓` walks forward only from the last. Mid-paragraph,
  both keys move the caret one row and leave the draft alone, matching terminal Pi's
  visual-line gate.
- **The arrow chords are explicit.** History is reached by plain `↑`/`↓` with a collapsed
  caret only. `Shift+↑` extends the selection, `Ctrl+↑`/`Meta+↑` move by word/paragraph,
  `Alt+↑` keeps the follow-up dequeue, and an active selection is never replaced by a
  recalled prompt.
- **The measurement is honest.** The caret row comes from an offscreen mirror of the
  textarea's computed text styles plus a one-character `Range` probe; every path that
  cannot measure layout — `line-height: normal`, a hidden box, jsdom — returns no row and
  the composer falls back to the old logical-line check.
- **Proven in a real layout.** jsdom has no layout, so the new unit tests drive the
  measurement with stubbed geometry and the edge decision without a DOM, while
  `tests/e2e/session.spec.ts` types a wrapped draft into the real app and proves that the
  value survives row-by-row caret movement and recalls only from the top.

## What changed since v0.10.0

### Prompt history gates on displayed rows

`src/renderer/src/session/textarea-visual-lines.ts` recreates the textarea's line layout:
an offscreen `pre-wrap` div carries the text-affecting computed styles (font, letter and
word spacing, tab size, text indent, line height, …), holds the same value plus a
zero-width-space sentinel so a trailing newline still creates its line box, and a
one-character `Range` probe reports the caret's row. A collapsed range cannot tell the two
sides of a soft-wrap boundary apart, which is why the probe is one character, not a point.
The row is clamped to the measured last row, and the result is `null` for `wrap="off"`, a
zero-width box, an unparseable `line-height`, or a missing `Range.getBoundingClientRect` —
the composer then falls back to logical lines exactly as before.

`atHistoryEdge()` in `prompt-history.ts` is the pure decision: `↑` enters history on row
0, `↓` walks forward on `visual.lastRow`, and the logical line numbers are only the
no-layout fallback. The Composer takes the key only when that gate says yes, and only for
a plain arrow with a collapsed caret. `Alt+↑` is still handled earlier as the queue
dequeue, and the completion menu, Escape and the follow-up chords keep their precedence.

### The chord table is no longer implicit

The old gate read the logical line count, so every row of a soft-wrapped paragraph looked
like the first and last line: `↑` replaced the draft and `↓` walked history from anywhere
inside it. It also answered `Shift+↑` and `Ctrl/Meta+↑`, which the browser should own. The
new gate is deliberately narrower:

| Chord                      | Result                                                         |
| -------------------------- | -------------------------------------------------------------- |
| `↑` / `↓`                  | native caret row; history only at the first/last displayed row |
| `Shift+↑` / `Shift+↓`      | native selection extension, never history                      |
| `Ctrl/Meta+↑` / `↓`        | native word/paragraph movement, never history                  |
| `Alt+↑`                    | dequeue the follow-up text (unchanged)                         |
| any arrow with a selection | native, never history                                          |

### CI E2E hardening

The hosted Windows runner does not deliver a synthetic drag to the rail splitter's 1 px
handle: `pointerdown` lands, the move never does. `tests/e2e/source-control.spec.ts` keeps
two real drag attempts (they pass locally and on a real desktop) and then resizes through
the component's own keyboard contract — `ArrowDown` on the focused separator — so the
geometry assertion still runs instead of being skipped. Pointer capture, the in-flight
preview and the clamp remain covered by `tests/renderer/block-splitter.test.tsx`.

## Install

Download from [GitHub Releases](https://github.com/dieuluucanh/pi-desktop/releases).

| Platform      | Artefacts                                                                                                              | Status  |
| ------------- | ---------------------------------------------------------------------------------------------------------------------- | ------- |
| Windows (x64) | `Pi-Desktop-0.10.1-win-x64-setup.exe` (NSIS), `Pi-Desktop-0.10.1-win-x64-portable.exe`                                 | primary |
| Linux         | `Pi-Desktop-0.10.1-linux-x86_64-appimage.AppImage`, `Pi-Desktop-0.10.1-linux-amd64-deb.deb` (x64) and the `arm64` pair | beta    |
| macOS         | `Pi-Desktop-0.10.1-mac-arm64.dmg`, `Pi-Desktop-0.10.1-mac-x64.dmg` (plus the `.zip` pair used by the updater)          | beta    |

Builds are **unsigned**. Windows SmartScreen warns on first launch (**More info → Run
anyway**). macOS additionally requires an explicit approval:

1. Open the `.dmg` and drag **Pi Desktop** into `/Applications`.
2. Launch it once. macOS refuses, and there is no right-click override any more.
3. Open **System Settings → Privacy & Security**, scroll to the bottom, and choose
   **Open Anyway** for Pi Desktop.

If the bundle reports that it is **damaged** instead (usually after unzipping the `.zip`
rather than mounting the `.dmg`), clear the quarantine flag and try again:

```bash
xattr -dr com.apple.quarantine "/Applications/Pi Desktop.app"
```

On Linux, the AppImage needs FUSE (`libfuse2`, or run with `--appimage-extract-and-run`);
install the `.deb` with `sudo apt install ./…deb` rather than `dpkg -i` so the
GTK/NSS/asound dependencies resolve. The app bundles its own Node runtime: no system
Node, npm or Pi install is needed.

## Known limitations in v0.10.1

Every known limitation is recorded here and in the user guide:

- **Unsigned builds** — SmartScreen/Gatekeeper warn on first launch; signing is deferred
  ([backlog](../product/backlog.md)).
- **macOS and Linux are beta** — built and structurally verified in CI, but no real macOS
  launch and no fresh Linux desktop install have been exercised by a person for this
  release. Windows is the verified target.
- **Prompt-history measurement needs a measurable line box** — the composer's `text-sm`
  keeps a numeric line height. A future style change to `line-height: normal`, a hidden
  composer or a browser without `Range` geometry falls back to the logical-line gate, and
  the soft-wrap behaviour returns to the old bug. The E2E test fails if that happens.
- **The mirror can drift at extreme settings** — font fallback, letter spacing, a
  fractional line height or a scrollbar-width change at unusual zoom can misclassify a
  caret exactly on a wrap boundary. The logical fallback and the clamped row keep the
  result sane; the manual zoom matrix was not re-walked for this release.
- **The updater** is verified against its policy and a fake port, not a live GitHub Release
  feed. macOS updates stay manual.
- **An updated package takes effect on the next session** — a running session keeps the
  code it loaded until **Reload runtime** (or a restart).
- **The bundled Pi agent is not user-updatable** — it moves with Pi Desktop. A stale agent
  is a release-pipeline warning by default, not a blocked tag, and a major is never taken
  automatically.
- **Upstream** SDK/provider changes can affect extensions and model behaviour; this release
  pins `@earendil-works/pi-coding-agent` 1.5.0 and requires the companion workflow
  extension 0.11.0 or newer for Review Mode.
- **Verified structurally, not on a live machine** — the Linux and macOS artefacts are
  built and structurally checked in CI; no person has launched every artefact on real
  hardware for this release. Review Mode's manual provider matrix (approve/deny, pause,
  resume, reload recovery) was not re-walked for this build.
- **The terminal is local only** — one shell per tab, no SSH/remote session, no tmux
  control mode and no docked split panel; it does not spawn in an untrusted project until
  you grant trust. The Linux native backend is built for **glibc 2.31 /
  `GLIBCXX_3.4.28`**.
- **Transcript find cannot mark across a soft break** — a query spanning a line break is
  counted by the matcher but one `<mark>` cannot span the rendered `<br>`; copy still uses
  the raw message text.
- **Informational notifications are hidden in the bell by default** — that switch scopes
  to the bell and toasts only; the transcript always shows the text. Hidden bell rows are
  never lost: **Show hidden (N)** reveals them.
- **Deferred features** are listed in [`../product/backlog.md`](../product/backlog.md).
