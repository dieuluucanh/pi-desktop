# Pi Desktop v0.12.0

**Release date:** 2026-11-28 · **Status:** published to GitHub Releases by
`.github/workflows/release.yml` on tag `v0.12.0` · **Pi SDK:**
`@earendil-works/pi-coding-agent` 1.7.0 · **Bundled Workflow:**
`@dieulc/workflow` 0.17.5 · **Bundled runtime:** Node 24.22.2

Pi Desktop is a standalone desktop app for the [Pi coding agent](https://pi.dev):
projects, sessions, chat, providers, models, extensions, packages, skills, themes and
settings in a UI, using the **same `~/.pi/agent` profile as terminal Pi**, so the two are
interchangeable. **Pi for Office is an optional integration**, not a built-in surface.

This is the eleventh public release, a **workspace and extension** release on top of
v0.11.0. It adds managed file attachments and document extraction, the generic extension
contribution contract and related sessions, the experimental Orchestrator, one working bar
with a mode cycle, prompt refinement, a full-width editor, rail scroll memory, native
commit-message generation, and several session-reliability fixes. It bundles Pi 1.7.0 and
the published `@dieulc/workflow` 0.17.5 artifact.

## Highlights

- **Managed file attachments.** The composer accepts files through a main-owned,
  tab-scoped draft: bounded import, previews, image preparation, document extraction,
  conversion proposals and approvals, durable session ownership, retention/tombstones,
  transcript cards, and share/bug-report sanitization. Attachment content never becomes a
  renderer-supplied path or an unchecked host field.
- **A generic extension seam.** Extensions publish modes, status, progress, actions,
  input availability and related-session links through one contribution contract. Desktop
  does not parse Workflow names or status prose.
- **Related sessions are normal tabs.** Source-bound ownership comes from the registered
  command, capability negotiation is explicit, bootstrap entries are bounded and written
  before `session_start`, and a duplicate request replays instead of opening a second child.
- **The Orchestrator is opt-in and experimental.** Entering the mode launches nothing.
  Ordinary Plan → Review → Build keeps its defaults; an approved plan can bind one in-process
  Build child per row, with parent-only commits and explicit pause/resume/abort controls.
- **One working bar and a mode cycle.** The separate extension bars became one working row
  with grouped actions and a mode menu; the composer's mode label is the mode-cycle control.
- **Prompt refinement.** `/prompt` and the one-shot composer control refine a drafted request
  through a host-agnostic contract with a per-tab operation, conflicts, cancel and recovery.
- **Editor, rail and commit workflow.** File editors fill the pane, the rail remembers its
  scroll position, the transcript follow is pinned, and the commit box can generate a message
  natively.
- **Session reliability.** Closing a starting session is a normal cancellation, one-shot
  completions carry a stable session id, and queued turns are attributed to their owner.

## What changed since v0.11.0

### Managed attachments and extraction

- The composer has a managed attachment tray with import, pick, preview, remove, readiness
  and delivery states; legacy image payloads remain supported on the standalone path.
- The main process owns the destination, bounded writes and the durable submission journal;
  the renderer receives grants, never trusted paths.
- Document extraction runs in a bounded worker. Versioned extraction contracts feed
  conversion proposals, which require explicit approval before durable content is created.
- Accepted originals and converted representations are promoted to profile-scoped
  session/branch owners. Retention and tombstones keep deleted-session copies recoverable
  for a bounded window; storage can be inspected and cleared explicitly.
- Attachment content is excluded from shares and bug reports, and the sanitized export
  uses one attachment-private projection. Native HTML/JSONL exports remain available with
  their own confirmation.

### Extension contract, related sessions and Orchestrator

- The host reads one generic contribution contract and advertises only the capabilities it
  actually wired. Missing native capabilities return an explicit `unsupported` result.
- Related sessions use a host-issued capability grant, a source-bound owner and a stable
  child identity; the parent never reaches a private attachment method through a generic
  request.
- The Orchestrator's parent tools bind, query and retry rows. A running child can be paused,
  resumed, aborted and inspected from the working bar; a reload blocks the running row and
  pauses the run instead of silently losing it.
- The Workflow artifact is pinned to the published npm `@dieulc/workflow@0.17.5` tarball by
  version and integrity. Desktop stages and verifies it after the host build in CI.

### Composer, working bar and prompt refinement

- The working bar replaces the old separate extension rows. It carries the working message,
  elapsed time, linked tab, lock marker, inline extension actions and a grouped dots menu.
- The composer mode label cycles modes; the mode menu and the working bar share the same
  contribution state.
- Prompt refinement has a per-tab operation lifecycle, one-shot arming, conflict handling,
  cancel/recovery, and a typed `ComposerSendDisposition` so a transform never clears the
  draft it is about to replace.

### Editor, rail, commit and session reliability

- The CodeMirror editor fills its pane instead of leaving a narrow column.
- The rail remembers per-section scroll positions, and the transcript follow is pinned while
  the user reads older output.
- The commit box can generate a commit message from the bounded staged diff.
- Closing a session while it is still starting is a normal cancellation; one-shot
  completions send a stable session id; queued turns carry their origin and owner.

### Pi SDK and bundled runtime

- The app moves from Pi 1.5.0 to **1.7.0**. The cache-miss toggle became four notice toggles
  (`notices.cacheMisses`, `notices.cacheWarming`, `notices.compactionCosts`,
  `notices.reasoningDrops`), and `cacheWarming` now defaults to `idle`.
- Pi 1.7.0 removed install telemetry and the `PI_TELEMETRY` switch. The app removed the
  corresponding setting, preference, privacy switch and spawn environment; the first-run
  screen is now a local-data notice.
- Extension components return `readonly string[]` in Pi 1.6+, so the host copies render
  output before applying a cursor. Package-manager progress accepts the SDK's `result` event.

## Install

Download from [GitHub Releases](https://github.com/dieuluucanh/pi-desktop/releases).

| Platform      | Artefacts                                                                                                              | Status  |
| ------------- | ---------------------------------------------------------------------------------------------------------------------- | ------- |
| Windows (x64) | `Pi-Desktop-0.12.0-win-x64-setup.exe` (NSIS), `Pi-Desktop-0.12.0-win-x64-portable.exe`                                 | primary |
| Linux         | `Pi-Desktop-0.12.0-linux-x86_64-appimage.AppImage`, `Pi-Desktop-0.12.0-linux-amd64-deb.deb` (x64) and the `arm64` pair | beta    |
| macOS         | `Pi-Desktop-0.12.0-mac-arm64.dmg`, `Pi-Desktop-0.12.0-mac-x64.dmg` (plus the `.zip` pair used by the updater)          | beta    |

Builds are **unsigned**. Windows SmartScreen warns on first launch (**More info → Run
anyway**). macOS additionally requires an explicit approval:

1. Open the `.dmg` and drag **Pi Desktop** into `/Applications`.
2. Launch it once. macOS refuses, and there is no right-click override any more.
3. Open **System Settings → Privacy & Security**, scroll to the bottom, and choose
   **Open Anyway** for Pi Desktop.

If the bundle reports that it is **damaged** instead (usually after unzipping the `.zip`
rather than mounting the `.dmg`), clear the quarantine flag and try again:

```bash
xattr -dr com.apple.quarantine "/Applications/Pi Desktop.app"
```

On Linux, the AppImage needs FUSE (`libfuse2`, or run with `--appimage-extract-and-run`);
install the `.deb` with `sudo apt install ./…deb` rather than `dpkg -i` so the
GTK/NSS/asound dependencies resolve. The app bundles its own Node runtime: no system
Node, npm or Pi install is needed.

## Updates

| Platform         | In-app check           | In-app install                             |
| ---------------- | ---------------------- | ------------------------------------------ |
| Windows          | yes, 10 s after launch | yes — download, then **Restart & install** |
| Linux (AppImage) | yes                    | yes                                        |
| macOS            | **no**                 | **no** — download the new `.dmg`           |

macOS updates stay download-only: Squirrel.Mac validates a downloaded update against the
running app's code-signing requirement, and an ad-hoc signature's requirement changes with
every build. **About & updates** says **Manual updates** and links to the Releases page.

v0.12.0 is the version an installed v0.11.0 build picks up (Windows and the Linux
AppImage). macOS stays manual.

## Verification

- The release change set runs `format:check`, `typecheck` (node, web, e2e), `lint`,
  `npm test`, `test:coverage`, `build`, `workflow:verify --offline --require-dev`,
  `site:check` and `site:build`.
- The release workflow runs `workflow:stage` and `workflow:verify` after the host build in
  every platform job, and `workflow:package:verify` against the packaged app before upload.
- The parity suite loads the real staged `@dieulc/workflow@0.17.5` artifact; with
  `PI_REQUIRE_WORKFLOW_BUNDLE=1` a missing bundle is a failure, not a skip.
- Attachment coverage includes the pure contracts, the main-owned store and journal, the
  extraction worker, conversion proposals, transcript projection and the sanitized export.
- Extension/related-session coverage includes the shared two-extension fixture and the
  host-contract E2E for arbitrary modes, cross-owner actions, stale epochs, reload, absent
  capabilities and source-bound related sessions.
- Not verified for this release: no live provider/turn loop, no real terminal automation,
  no packaged Desktop walkthrough and no live platform signoff. The Workflow artifact was
  re-verified from its published bytes, but manual child TODO acceptance remains **NOT RUN**.

## Known limitations

- **Unsigned builds** — SmartScreen and Gatekeeper warn on first launch; code signing is
  deferred to the backlog.
- **macOS and Linux are beta** — both are built and structurally verified in CI, but no
  person launched the macOS artifact and no fresh Linux desktop install was exercised for
  this release. Windows is the primary verified target.
- **The Orchestrator is experimental** — it is opt-in, automated checks do not establish a
  real-provider or live child-session acceptance, and the live checklist remains **NOT RUN**.
- **Managed attachments are new** — extraction and conversion are bounded and fail closed,
  but they depend on provider/model image and context limits. A conversion proposal is not a
  send; an accepted attachment is not proof that a provider retained or read it.
- **Pi 1.7.0 removed install telemetry** — there is no install-telemetry switch in either
  Pi or Desktop; the first-run privacy screen is a local-data notice.
- **Upstream** — the bundled Workflow is the published `@dieulc/workflow@0.17.5`; Desktop
  does not parse its names or status prose. A live provider/terminal walkthrough and the
  Workflow repository's `docs/orchestrator-live-acceptance.md` remain **NOT RUN**.
- **Verified structurally, not on a live machine** — the cross-platform release gate is a
  dry run on the exact commit; the tag run is the first full Windows, macOS and Linux build.
