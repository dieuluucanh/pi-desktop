# Pi Desktop v0.10.0

**Release date:** 2026-11-15 · **Status:** published to GitHub Releases by
`.github/workflows/release.yml` on tag `v0.10.0` · **Pi SDK:**
`@earendil-works/pi-coding-agent` 1.5.0 · **Companion extension:**
`@dieulc/workflow` ≥ 0.11.0 · **Bundled runtime:** Node 24.22.2

Pi Desktop is a standalone desktop app for the [Pi coding agent](https://pi.dev):
projects, sessions, chat, providers, models, extensions, packages, skills, themes and
settings in a UI, using the **same `~/.pi/agent` profile as terminal Pi**, so the two are
interchangeable. **Pi for Office is an optional integration**, not a built-in surface.

This is the eighth public release, an **update-awareness and chat-parity** release. The
app now checks installed packages for newer versions and surfaces them without ever
updating without consent, and the bundled Pi agent has its own release-pipeline channel
instead of being frozen by hand. Extension command output (`ctx.ui.notify`) always reaches
the transcript, as in terminal Pi. The transcript fills the pane at every zoom level, the
notification bell is a real dismissable popover, and the recommended extension set was
refreshed. The `checks` matrix is green on Windows, macOS and Linux again.

## Highlights

- **Extension update checks.** A background sweep asks the Pi SDK's own
  `checkForAvailableUpdates()` about every installed package (about 20 s after launch,
  then every six hours, switchable), and **Check now** / opening **Extensions → Packages**
  always checks. An outdated row shows `1.6.0 available` (or `update available` for a
  Git/ranged source), the **Extensions** sidebar item gets a dot, and one bell row
  (**Extension updates**, its own Settings switch) offers **View extensions**. A pin is
  respected: a pinned row never badges, and update/update-all stay consent-gated.
- **The bundled Pi agent moves before the tag.** `npm run pi:status` / `pi:check` /
  `pi:update` compare the pinned `@earendil-works/pi-coding-agent` with npm's `latest`,
  derive the sibling and `typebox` pins from the SDK's own published manifest, and
  refuse to take a major automatically. A daily `pi-agent-watch` workflow opens the PR,
  and the release `prepare` job repeats the check — a warning by default, a hard failure
  when the operator asks for it. The packaged agent version is stamped into
  `build-info.json` and shown in **About & updates** and Diagnostics.
- **Command output is chat content.** Every `ctx.ui.notify` now renders in the transcript
  whatever the notification class or mute rules say, matching terminal Pi's
  `showStatus`/`showWarning`/`showError`. Classes and mutes keep their real job: the bell
  and toasts. `/profile list`, `/folder-policy status` and every other multi-line command
  output keeps its lines and becomes visible under the default preferences.
- **The transcript fills the pane.** The `110ch` measure cap is gone, so the transcript
  column is the pane width minus the scroller gutter at every zoom level; zooming out
  adds content, not blank gutters.
- **The bell is a real popover.** Built on the owned Radix `Popover` primitive, it closes
  on an outside click or Escape, returns focus to the bell, and keeps a native web tab
  from covering it. Escape no longer reaches the app-wide "stop the run" binding while
  the panel is open, and the redundant header `×` is gone.
- **A refreshed recommended set.** Seven packages, alphabetical:
  `@dieulc/autocompact`, `@dieulc/pi-office-bridge`, `@dieulc/workflow`,
  `@plannotator/pi-extension`, `pi-lens`, `pi-memory`, `pi-web-access`.
  `@dieulc/server-logs` and `pi-commandcode-provider` remain installable from
  **Packages**; they are no longer recommended cards.
- **CI is green again.** The checks matrix failed on all three runners before this
  release. The fix is a set of real causes, not skips: LF pins for the vendored manifest
  and imported scripts, host-native path fixtures, `realpath` comparisons, platform-aware
  live gates, explicit trust answers in live tests, and deterministic E2E waits.

## What changed since v0.9.0

### Extension updates are visible, never automatic

`packages.checkUpdates` is a new read-only host method (allowed in safe mode: it loads no
package code) that wraps the SDK's `DefaultPackageManager.checkForAvailableUpdates()`.
It answers one snapshot — `{updates, checkedAt, offline}` — cached per resolved project
cwd for 60 s, coalescing in-flight calls; a successful install/update/remove clears the
cache. One extra `npm view <name> version --json` fills `latestVersion` only for a
floating `npm:` source, compared with the app's existing `compareVersions`.

The renderer owns the schedule because it owns the active project: ~20 s after launch and
every six hours when **Check automatically** is on. A failed check never truncates the
known list and never toasts; it keeps the previous snapshot and shows a muted inline line.
Offline (`PI_OFFLINE`) pauses the sweep with an explicit status. Update / Update all are
unchanged and still run through the consent dialog.

Notifications dedupe by the update _set_, not by a version: `prefs.packages.notifiedSignature`
is a stable hash of the sorted `source@latestVersion` segments, so dismissing a set keeps
it dismissed while a new package or a newer target raises a new row. The new `extension`
notification class is on by default and has its own Settings switch.

### The Pi agent is kept current before the tag

The app ships its agent, so a user updates it by updating Pi Desktop. Two automations keep
that honest without letting a tag build mutate its own source:

- `pi-agent-watch.yml` runs daily (and on demand), reads npm's `latest`, and opens a PR
  when a minor/patch is behind. A major is reported (`major-behind`) and never bumped
  automatically.
- `release.yml` `prepare` repeats the check in the job summary. A stale agent is a warning;
  `require_latest_pi=true` on a dispatch makes it a hard failure. An unreadable registry is
  always a warning: a release must not depend on npm being up.

`npm run pi:update` reads the target SDK's own manifest for its sibling and `typebox`
versions, rewrites `package.json` and `docs/architecture/versions.md`, and runs the gates.
`tests/packaging/pi-pins.test.ts` enforces the contract the automation relies on.

### Every extension notification prints

`NoticeView` no longer consults notification preferences. `ctx.ui.notify` is chat content;
classes and mute rules are bell/toast policy. The `info` class still starts off for the
bell and toasts, but its text is visible in the transcript — which is where terminal Pi
puts it. Only an immediately repeated identical `oi.notify` collapses; a repeat after other
content appends. A host-level audit now exercises the notify, status, message, entry,
dialog and TUI channels through `commands.run`, and an E2E test seeds a command.

### The transcript uses the width it is given

The content column lost `mx-auto` and `max-w-[var(--transcript-measure)]`, and the
`--transcript-measure` token was deleted rather than left as a dead knob. The column is
the pane width minus the scroller's `px-4` gutter in both the plain and virtualized paths;
per-message percentages (85 %/95 %) still resolve against it. An E2E test walks the zoom
levels and asserts the column tracks `pane − 32` and actually grows past the retired cap.
Long prose lines on wide displays are the accepted trade-off.

### The notification bell dismisses like a layer

`src/renderer/src/ui/popover.tsx` is a new owned primitive over `@radix-ui/react-popover`.
The bell uses it, so outside pointerdown and Escape close the panel, focus returns to the
trigger, and placement is collision-aware. Because Radix portals the content and sets
`data-state`, the existing overlay detector recognises it and a native `WebContentsView`
cannot paint over it. The header `×` is gone; **Clear**, **Show hidden**, **Show**,
**Unmute** and the per-row `×` do not close the panel, while cross-surface actions
(notification settings, the mute dialog, **View update**, **View extensions**) close it
first.

### Cross-platform checks are honest

The `checks` matrix had been red since before v0.9.0. This release fixes the causes:

- `.gitattributes` pins the vendored Office manifest, `scripts/*.mjs` and `*.sh` to LF —
  Vitest's inlined runner cannot import a hashbang followed by CRLF, and the manifest lock
  stores the sha256 of the exact bytes. Imported scripts also lost their shebangs.
- Path fixtures are built with the host path flavour, and real-git assertions compare
  `realpath` on both sides (macOS `/private/var`, Windows short names).
- Live suites are gated on what they actually require: a bundled runtime (a system-Node
  fallback is not one), Office apps where the platform reports them, provider credentials
  in a throw-away profile, and an explicit trust answer.
- E2E polls for the splitter preview instead of reading it in the same task, and the
  git-missing case no longer strips Node from `PATH`.
- The node-pty `spawn-helper` permission fix now runs from `postinstall` and the checks
  workflow, so a dev checkout on macOS cannot hit the opaque `posix_spawnp failed`.
- `session.resume` carries the tab's trust answer, so a restarted host does not re-prompt
  after a crash (a `"session"` grant does not survive process death).
- `.pi/settings.json` stays untracked, with a tracked `.pi/settings.example.json` and a
  documented policy: machine-local grants belong to the contributor, a curated project
  file is a legitimate choice for other repositories.

## Install

Download from [GitHub Releases](https://github.com/dieuluucanh/pi-desktop/releases).

| Platform      | Artefacts                                                                                                              | Status  |
| ------------- | ---------------------------------------------------------------------------------------------------------------------- | ------- |
| Windows (x64) | `Pi-Desktop-0.10.0-win-x64-setup.exe` (NSIS), `Pi-Desktop-0.10.0-win-x64-portable.exe`                                 | primary |
| Linux         | `Pi-Desktop-0.10.0-linux-x86_64-appimage.AppImage`, `Pi-Desktop-0.10.0-linux-amd64-deb.deb` (x64) and the `arm64` pair | beta    |
| macOS         | `Pi-Desktop-0.10.0-mac-arm64.dmg`, `Pi-Desktop-0.10.0-mac-x64.dmg` (plus the `.zip` pair used by the updater)          | beta    |

Builds are **unsigned**. Windows SmartScreen warns on first launch (**More info → Run
anyway**). macOS additionally requires an explicit approval:

1. Open the `.dmg` and drag **Pi Desktop** into `/Applications`.
2. Launch it once. macOS refuses, and there is no right-click override any more.
3. Open **System Settings → Privacy & Security**, scroll to the bottom, and choose
   **Open Anyway** for Pi Desktop.

If the bundle reports that it is **damaged** instead (usually after unzipping the `.zip`
rather than mounting the `.dmg`), clear the quarantine flag and try again:

```bash
xattr -dr com.apple.quarantine "/Applications/Pi Desktop.app"
```

On Linux, the AppImage needs FUSE (`libfuse2`, or run with `--appimage-extract-and-run`);
install the `.deb` with `sudo apt install ./…deb` rather than `dpkg -i` so the
GTK/NSS/asound dependencies resolve. The app bundles its own Node runtime: no system
Node, npm or Pi install is needed.

## Updates

| Platform         | In-app check           | In-app install                             |
| ---------------- | ---------------------- | ------------------------------------------ |
| Windows          | yes, 10 s after launch | yes — download, then **Restart & install** |
| Linux (AppImage) | yes                    | yes                                        |
| macOS            | **no**                 | **no** — download the new `.dmg`           |

macOS updates stay download-only: Squirrel.Mac validates a downloaded update against the
running app's code-signing requirement, and an ad-hoc signature's requirement changes with
every build. **About & updates** says **Manual updates** and links to the Releases page.

v0.10.0 is the version an installed v0.9.0 build picks up (Windows and the Linux
AppImage). macOS stays manual.

## Known limitations in v0.10.0

Every known limitation is recorded here and in the user guide:

- **Unsigned builds** — SmartScreen/Gatekeeper warn on first launch; signing is deferred
  ([backlog](../product/backlog.md)).
- **macOS and Linux are beta** — built and structurally verified in CI, but no real macOS
  launch and no fresh Linux desktop install have been exercised by a person for this
  release. Windows is the verified target.
- **Extension update checks are registry-based** — they need the network, pause under
  `PI_OFFLINE`, and can lag a fresh publish by a few seconds; **Check now** re-reads. A
  pinned package is skipped by design, and a Git or ranged source has no single target
  version to name.
- **An updated package takes effect on the next session** — a running session keeps the
  code it loaded until **Reload runtime** (or a restart).
- **The bundled Pi agent is not user-updatable** — it moves with Pi Desktop. A stale agent
  is a release-pipeline warning by default, not a blocked tag, and a major is never taken
  automatically.
- **macOS updates are manual** — an ad-hoc signature cannot satisfy Squirrel.Mac, so the
  app links to the release instead of offering an in-place install.
- **The updater** is verified against its policy and a fake port, not a live GitHub Release
  feed.
- **Upstream** SDK/provider changes can affect extensions and model behaviour; this release
  pins `@earendil-works/pi-coding-agent` 1.5.0 and requires the companion workflow
  extension 0.11.0 for Review Mode.
- **Verified structurally, not on a live machine** — the Linux and macOS artefacts are
  built and structurally checked in CI; no person has launched every artefact on real
  hardware for this release. Review Mode's manual provider matrix (approve/deny, pause,
  resume, reload recovery) was not re-walked for this build.
- **The terminal is local only** — one shell per tab, no SSH/remote session, no tmux
  control mode and no docked split panel; it does not spawn in an untrusted project until
  you grant trust. The Linux native backend is built for **glibc 2.31 /
  `GLIBCXX_3.4.28`**.
- **Transcript find cannot mark across a soft break** — a query spanning a line break is
  counted by the matcher but one `<mark>` cannot span the rendered `<br>`; copy still uses
  the raw message text.
- **Informational notifications are hidden in the bell by default** — that switch now
  scopes to the bell and toasts only; the transcript always shows the text. Hidden bell
  rows are never lost: **Show hidden (N)** reveals them.
