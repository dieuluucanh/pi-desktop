# Pi Desktop v0.3.0

**Release date:** 2026-11-01 · **Status:** development build, built locally (not
published to GitHub Releases) · **Pi SDK:** `@earendil-works/pi-coding-agent`
1.4.0 · **Bundled runtime:** Node 24

Pi Desktop is a standalone desktop app for the [Pi coding agent](https://pi.dev):
projects, sessions, chat, providers, models, extensions, packages, skills, themes
and settings in a UI, using the **same `~/.pi/agent` profile as terminal Pi**, so
the two are interchangeable. **Pi for Office is an optional integration**, not a
built-in surface.

This is the third tagged release. It keeps the 1.4.0 SDK pin and the profile
contract from v0.2.0 and finishes the interface pass that the previous release
only outlined: session-first chrome, one Send, copyable output everywhere,
editable high-contrast themes, display zoom, muteable notifications, a
project-scoped rail with draggable blocks, honest git sync feedback and
one-line commit history with a hover card. Folder checkpoints now snapshot once
per prompt, and the Office bridge only starts when asked.

## Install

The artefacts below are produced locally under `release/`. They are equivalent
in layout to the v0.2.0 assets, with the version updated.

| Platform | Artefacts                                                                                                            | Status    |
| -------- | -------------------------------------------------------------------------------------------------------------------- | --------- |
| Windows  | `Pi-Desktop-0.3.0-win-x64-setup.exe` (NSIS), `Pi-Desktop-0.3.0-win-x64-portable.exe`                                 | primary   |
| Linux    | `Pi-Desktop-0.3.0-linux-x86_64-appimage.AppImage`, `Pi-Desktop-0.3.0-linux-amd64-deb.deb` (x64) and the `arm64` pair | beta      |
| macOS    | `.dmg`, `.zip` (arm64 + x64)                                                                                         | not built |

Builds are **unsigned**. Windows SmartScreen and macOS Gatekeeper warn on first
launch; the guide has the per-platform steps (including the Linux FUSE and
`apt install ./…deb` notes). The app needs no pre-installed Node and no
pre-existing Pi — the runtime is bundled.

**Distribution status.** No GitHub Release is created for this build, so the
`electron-updater` feed (`latest.yml`, `latest-linux*.yml`) has not been
advanced. Installed v0.2.0 builds will therefore not see v0.3.0 until the
artefacts are uploaded to a release with the usual tag. Locally packaged
installers are stamped `local` in `resources/build-info.json` and do not run
automatic update checks; a manual check reports the neutral “No published release
was found for this build” state, never a failure banner.

## What changed since v0.2.0

### Session-first chrome

- **The transcript owns the view.** The title bar and the session header are
  gone; the project path moved to the status bar, the model / thinking / context
  controls sit above Send, and the sidebar's project actions collapsed into a
  `+` menu.
- **`SessionFooter` replaces `ComposerFooter`.** One responsive status rail
  merges single-line below-editor widgets into footer columns, follows
  `ctx.ui.setFooter` / `setStatus`, and shows `pwd (branch)`, tokens/cost/context,
  extension statuses and `model • level`.
- **One thinking vocabulary.** `src/shared/thinking.ts` owns the seven canonical
  levels, their descriptions, fills and order. The picker is model-aware, and the
  model picker previews per-model support through a new host SDK adapter.
- **The workflow mode badge** moved to the input's top-right and carries the
  border's tone.

### Composer, copy and zoom

- **One Send.** The steer/follow-up toggle, `SendMode` and the
  Normal/Verbose/Summary view modes are gone: Enter steers, `Alt+Enter` queues a
  follow-up, and `Ctrl+O` is the one tool-detail switch.
- **One clipboard path.** Transcript messages, checkpoint refs, Office document
  ids, the Office diagnostics bundle and extension TUI frames all copy through
  `ui/clipboard.ts`, with a legacy fallback and an honest failure message.
  Extension surfaces get a Copy button, `Ctrl/Cmd+C` copies a real selection
  instead of forwarding `^C`, and ANSI escapes are stripped from frame text.
- **A real context menu.** Electron has no default right-click menu, so a pure,
  unit-tested template (Undo/Redo/Cut/Copy/Paste/Select All) is popped from the
  main process.
- **Display zoom.** Thirteen levels from 50 % to 300 %, persisted in
  `prefs.zoomFactor`, applied with `webContents.setZoomFactor`, bound to
  `CmdOrCtrl+= / - / 0`, and exposed in the status bar and Settings.
- **Composer ergonomics.** One `useAutoGrowTextarea` hook grows the session
  prompt to 192 px and the commit message to 160 px before scrolling; the 28 px
  model/thinking/attach/Send/Stop controls stretch to the textarea height; the
  footer is a fixed 40 px viewport that wraps and scrolls instead of resizing the
  transcript.

### Themes and notifications

- **Editable high-contrast themes.** App-owned chrome tokens
  (`line`/`line-strong`/`raised`/`sunken`, plus a themeable `info` used by the
  `origin/main` chip), per-theme colour overrides persisted in
  `prefs.themeColors` and sanitized on read, and real colour controls on the
  active theme card. The active theme loads at startup, and follow-system
  appearance switches the built-in dark/light pair as the OS changes.
- **One theme surface.** The catalogue card is the control (role=radio), Settings
  no longer duplicates the picker, and activating a theme now reports failure
  instead of pretending.
- **Muteable notifications.** A shared mute model (exact text, a
  variable-erasing template signature, or a whole type) persisted under
  `prefs.notifications`; a gear on warning/error toasts plus a Mute dialog, a
  mute-aware history centre and a Settings → Notifications card. Muted arrivals
  stay archived and are only hidden from the transcript and toasts; identical
  `oi.notify` messages are deduped and their toasts collapse per tab.
- **Shell ergonomics.** The sidebar is resizable (200–520 px) and collapsible,
  inline rename replaces the modal dialog on sidebar and tab rows, and one shared
  `TabMenu` serves both surfaces.

### Source control and checkpoints

- **A project-scoped rail.** The rail moved into the app shell, so it exists
  beside Welcome too and follows the sidebar's selected project instead of the
  active tab (`railScopeFolder`: selected project, then tab cwd, then nothing).
  Source Control is three draggable blocks with pinned scope lines, persisted as
  `prefs.rail.split` / `prefs.rail.collapsed`; splitters only write on release.
  The per-entry reorder `⋯` menu was removed — drag is the one reorder path.
- **Honest sync feedback.** A killed child is classified as `timeout` with its
  duration; network actions keep a per-folder `gitSync` state, disable all three
  verbs while running, and render a spinner plus a Retry/Dismiss line where the
  user clicked. A successful line dismisses itself after 4 s; errors stay.
- **History that is actually current.** Chip text comes from git's `%D`, so an
  unpushed tip is never labelled `origin/main`; each log page is keyed to the
  repo state, so a commit, fetch, push or branch switch reloads it.
- **One-line commit rows with a hover card.** `readLog` carries the message body;
  each row is a single `h-6` line (icon, subject, folded refs, `+N`), and a
  portaled Radix HoverCard shows the full message, every raw ref, the author,
  absolute/relative date and the full sha, with Copy hash / Copy message.
- **Direct git writes.** The session consent gate, its dialog and
  `GIT_MUTATING_ACTIONS` are gone. Destructive operations keep their own
  confirmations: discard, a dirty-tree branch switch and drop-stash.
- **Checkpoints snapshot per prompt.** The extension listens to Pi's `input`
  event — once per prompt, steer and follow-up included — links the oldest
  pending snapshot to `turn_end`, and flushes leftovers as unlinked files-only
  entries at `agent_settled` / `session_shutdown`. `/checkpoint` (formerly
  `/rewind`) offers Files only for unlinked prompts, and failures notify once per
  reason. The rail and Settings copy now says “Prompt” / “automatic”.
- **One extension identity.** Host resolution prefers a profile clone, then the
  npm package, then the bundled copy, so `/checkpoint` never registers twice and
  `host.hello` reports which source was found. `npm run sync:extension` keeps a
  `~/.pi` package copy in step with the built artifact.
- **The publishable package.** `packages/checkpoints` ships
  `@dieulc/checkpoints@0.1.2` (independent version line, unchanged by this app
  release), and post-write verification now runs from the repository root.

### Office integration

- **The bridge starts on demand.** It no longer binds port 38617 just because a
  session opened; it stays down until `/office connect` or an explicit action.
- **Owner-aware controls.** The app reads the owner and `manualLifecycle` from
  bridge `/health` (0.6+) and can move the bridge between sessions without
  restarting either. The Documents row is rebuilt around Connect / Start a
  session / Disconnect / Restart / Open host / Move bridge here / Take over /
  Update bridge / Re-check, with confirmations for move and takeover.
- **No more port races.** Promotion frees an occupied port only after proving the
  owner, never signals this app's own PIDs or PIDs ≤ 4, re-reads the owner before
  each signal, rolls the displaced host back on failure, and shutdown now awaits
  the child's exit.
- **The setup wizard** gained an injected `ensureBridge` step that runs before
  Office opens, retries on verify, and feeds the `bridge-listening` checklist.

### Fixes

- Checkpoint prune ordering now grows with recency, and duplicate transcript
  hydration is guarded.
- `!` / `!!` keeps the session receiver, completes workspace paths, and shows a
  shell chip that says whether output stays in context.
- Fetch names the remote it talks to, and a failed `--set-upstream` retry reports
  its own error instead of repeating `no_upstream`.
- Installers now carry one Node runtime: `afterPack` prunes
  `resources/runtime/node` to the platform/arch being packaged, which also lets
  the Windows NSIS step build from a tree that holds a Linux runtime.

## Known limitations

Everything below is a real, user-visible limitation of v0.3.0, not a claim that
the feature is missing. The automated suite covers the logic; the items marked
“unverified on a real machine” need hardware/providers the build host does not
have.

### Platform and distribution

- **Unsigned builds.** SmartScreen/Gatekeeper warnings on first launch; signing
  and notarization are deferred ([backlog](../product/backlog.md)).
- **macOS and Linux are beta.** macOS was not built for this release: it needs a
  Mac for a meaningful `.dmg`/`.zip`. The Linux AppImage and `.deb` for x64 and
  arm64 were built in WSL2 (Ubuntu 26.04) and verified structurally (deb
  metadata and file list, one bundled runtime per architecture, the packaged
  host bundle, the `.desktop` entry, and the AppImage ELF header and size).
  They have still not been installed or run on a real Linux desktop, and the
  arm64 binaries cannot be executed on the x64 build host.
- **The Windows installer builds, but has not been installed on a clean VM.**
  `package:win` produces both artefacts with URL-safe, target-distinct names;
  the clean-VM install and first session remain the manual acceptance gate.
- **The updater was not exercised against a live feed.** This build published no
  GitHub Release, so no download → restart → install round trip happened.

### Verified structurally, not on a live machine

- **Provider sign-in** (OAuth device/code flows) against real providers; the
  request/response plumbing and redaction are unit-tested.
- **Extension UI fidelity**: a real extension's `notify`/`status`/`widget`,
  `ctx.ui.custom()` overlays, footers/headers/custom editors and custom
  `renderCall`/`renderResult` renderers in the packaged app.
- **Office**: the wizard acceptance row (detect → install → sideload → verify)
  and the bridge end to end (a real pane attached, `document:"active"` following
  focus, `#name` routing). Automated tests use scripted `/health` and fake
  runners.
- **Plannotator review round trip** and the in-app web tab.
- **Web-tab isolation on a loaded page**: creation flags are asserted, not a real
  page proving `window.pi` is absent.
- **Reliability**: crash/timeout banners against a real wedged host, safe mode
  against a genuinely broken extension, and the diagnostics bundle from a real
  run with real credentials.
- **Performance**: 60 fps is asserted structurally, and the RSS/restart budgets
  use injected samples.
- **The session surface against a live model**: the reducer, hydration, tool
  pairing and command paths are fixture-tested; a full live session with every
  new command has not been walked end to end since the chrome rewrite.
- **Drag and zoom feel**: splitter, sidebar and textarea gestures are
  pointer-tested in jsdom, not measured on a real display or trackpad.

### Upstream (not fixable in this app)

- **Pi's own writers are not crash-atomic.** `SettingsManager` writes
  `settings.json` with `writeFileSync`, and `SessionManager` appends/rewrites
  session JSONL with `appendFileSync`/`writeFileSync`. The app cannot patch the
  pinned SDK, so a crash _during Pi's own flush_ can still truncate those files.
  The app's own profile writes are atomic and `fsync` before the rename.
- **MCP is parity, not a built-in.** Like terminal Pi, MCP is reached through an
  installed extension; there is no first-party bridge
  ([backlog](../product/backlog.md)).
- **Backups cover `settings.json`**, not every profile file. `models.json`,
  `keybindings.json` and imported themes are written atomically but are not
  backed up before the first app write.
- **Phase G (update channels) is deferred.** The app updates its own code only;
  the Pi runtime and installed extensions have no update channel yet.

### Deliberately deferred

See [`../product/backlog.md`](../product/backlog.md) for the full list with
reasons: in-app terminal tab, native Plan/Review workspace, SQLite session
index/search, i18n, git worktrees, first-party MCP bridge, multi-window/scheduled
tasks/cloud sessions, code signing, and the external-editor launcher.

## Data, privacy and updates

- The app shares `~/.pi/agent` by default (settings, `auth.json`, sessions,
  extensions, packages). The onboarding profile step can keep a private profile
  under `userData` instead; the choice applies on the next launch.
- **Telemetry is off unless explicitly enabled.** The app sets
  `PI_TELEMETRY=0` for every host unless the preference is on, and never rewrites
  the shared `settings.json` for it.
- `auth.json` is Pi's and written `0600`; no IPC channel returns credential
  material, and the diagnostics bundle is redacted.
- Writes to the profile go through Pi's SDK managers or the app's atomic helpers
  (temp file → `fsync` → rename). A malformed `settings.json`, `auth.json` or
  `app-state.json` is reported and left untouched, never repaired silently.
- `@dieulc/checkpoints` keeps its own version line; installing it in terminal Pi
  reads the same shadow checkpoints the app writes.

## Verification status

- **Automated (green on the release tree):** `format:check`, `typecheck`,
  `lint` (0 errors), `test` (unit + renderer + packaging), `build` and
  `runtime:verify`.
- **Windows packaging:** the Windows targets are packaged with
  `electron-builder --win --publish never` after `npm run build` and
  `npm run runtime:verify`, producing `Pi-Desktop-0.3.0-win-x64-setup.exe` and
  `Pi-Desktop-0.3.0-win-x64-portable.exe`; `latest.yml` names the setup file.
  The `afterPack` hook pruned `linux-x64`/`linux-arm64` from the packaged app
  (the build log names them), the NSIS payload contains only the `win32-x64`
  runtime, and both installers are 183 MB.
- **Linux packaging:** built in WSL2 (Ubuntu 26.04, Node 24.21.0) after
  `runtime:fetch --platform linux-x64` and `--platform linux-arm64`,
  `runtime:verify` (11/11) and `electron-builder --linux --x64 --arm64
--publish never`. Each `.deb` was checked with `dpkg-deb -I/-c` (package,
  version 0.3.0, architecture, maintainer, depends; exactly one bundled runtime,
  `linux-x64` or `linux-arm64`; `app.asar.unpacked/out/host/index.mjs`;
  `pi-desktop.desktop`), and both AppImages have the ELF header and a sane size.
- **macOS:** not built for this release; it needs a Mac plus signing.
- **Manual (still the release gate):** the clean-machine install and first
  session with real providers (and a real Office install for the integration),
  on Windows and, for the beta, a real Linux desktop.
