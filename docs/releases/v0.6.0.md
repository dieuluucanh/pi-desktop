# Pi Desktop v0.6.0

**Release date:** 2026-11-05 · **Status:** published to GitHub Releases by
`.github/workflows/release.yml` on tag `v0.6.0` · **Pi SDK:**
`@earendil-works/pi-coding-agent` 1.4.0 · **Bundled runtime:** Node 24

Pi Desktop is a standalone desktop app for the [Pi coding agent](https://pi.dev):
projects, sessions, chat, providers, models, extensions, packages, skills, themes and
settings in a UI, using the **same `~/.pi/agent` profile as terminal Pi**, so the two are
interchangeable. **Pi for Office is an optional integration**, not a built-in surface.

This is the second public release. It fixes the one class of change the Source Control
menu used to lose — **new files created in a brand-new folder** — and makes an untracked
file a first-class row: its own `U` row, a full-file diff with every line added, an
_Open file_ action, and whole-file staging. A slow repository is now reported as slow
instead of being mistaken for "not a repository". The product site remains one page;
its docs are regenerated from `docs/` at build time.

## Install

Download from [GitHub Releases](https://github.com/dieuluucanh/pi-desktop/releases).

| Platform      | Artefacts                                                                                                            | Status  |
| ------------- | -------------------------------------------------------------------------------------------------------------------- | ------- |
| Windows (x64) | `Pi-Desktop-0.6.0-win-x64-setup.exe` (NSIS), `Pi-Desktop-0.6.0-win-x64-portable.exe`                                 | primary |
| Linux         | `Pi-Desktop-0.6.0-linux-x86_64-appimage.AppImage`, `Pi-Desktop-0.6.0-linux-amd64-deb.deb` (x64) and the `arm64` pair | beta    |
| macOS         | `Pi-Desktop-0.6.0-mac-arm64.dmg`, `Pi-Desktop-0.6.0-mac-x64.dmg` (plus the `.zip` pair used by the updater)          | beta    |

Builds are **unsigned**. Windows SmartScreen warns on first launch (**More info → Run
anyway**). macOS additionally requires an explicit approval:

1. Open the `.dmg` and drag **Pi Desktop** into `/Applications`.
2. Launch it once. macOS refuses, and there is no right-click override any more.
3. Open **System Settings → Privacy & Security**, scroll to the bottom, and choose
   **Open Anyway** for Pi Desktop.

If the bundle reports that it is **damaged** instead (usually after unzipping the `.zip`
rather than mounting the `.dmg`), clear the quarantine flag and try again:

```bash
xattr -dr com.apple.quarantine "/Applications/Pi Desktop.app"
```

On Linux, the AppImage needs FUSE (`libfuse2`, or run with
`--appimage-extract-and-run`); install the `.deb` with `sudo apt install ./…deb` rather
than `dpkg -i` so the GTK/NSS/asound dependencies resolve. The app bundles its own Node
runtime: no system Node, npm or Pi install is needed.

macOS updates stay download-only: Squirrel.Mac validates a downloaded update against
the running app's code-signing requirement, and an ad-hoc signature's requirement
changes with every build. **Settings → About & updates** says **Manual updates** and
links to the Releases page. A Developer ID certificate (or a stable self-signed release
certificate) is what turns this back on.

v0.6.0 is the first release an installed v0.5.0 build can see on the live feed, so the
download → restart → install path gets its first real test here (Windows and Linux
AppImage; macOS stays manual).

## What changed since v0.5.0

### Source control: new files are no longer invisible

The reported bug was precise: a file created by an agent in a **brand-new folder** did
not appear in _Changes_, so a commit-all silently left it out. The cause was `git
status` running without `--untracked-files=all`: git's default collapses an untracked
directory into one `? <dir>/` record, and a trailing-slash path is refused by the wire
sanitizer before the rail sees it.

- **Every untracked file is its own row.** `readStatus` now asks git for
  `--untracked-files=all` (VS Code does the same). A new module, a new package, a new
  docs folder — each file appears with a `U` badge, the header count includes it, and
  _Stage all_ / commit-all include it.
- **Nested repositories are skipped deliberately.** With `-uall` the only remaining
  trailing-slash record is another repository (git refuses to descend into it). This app
  has no nested-repo discovery, so a non-diffable folder row that stages a gitlink is
  worse than leaving it to the Explorer.
- **An untracked file opens a full-file diff.** `git diff` has no index side for an
  untracked file, so `src/git/untracked.ts` reads the work-tree bytes through the
  editor's own `readWorkspaceContent` (realpath containment, the 2 MB diff cap, UTF-8
  BOM stripping, binary/UTF-16 detection) and synthesises one all-added section: header
  `-0,0 +1,N`, every line an addition, and a `\ No newline at end of file` marker when
  the file has none. A binary file shows one honest "binary" row; an oversized file
  shows the viewer's too-large notice.
- **Whole-file staging only for a new file.** A partial new file is not a sound index
  state, so the diff viewer offers no _Stage hunk_ button for an untracked row; the
  Changes row's _Stage_ action stages the file.
- **Rows now act where they read.** Clicking a row's path (or its _Show diff_ icon)
  opens the side the group represents: the index side under _Staged Changes_, the work
  tree under _Changes_, and the synthesised addition for an untracked file. Hover actions
  are _Show diff_, _Open file_, _Stage_/_Unstage_ and _Discard_. _Open file_ is hidden
  for a deleted path. Rows are rendered in path order (numeric-aware, case-insensitive),
  so a new file cannot sink below a long list of modifications.
- **A slow status is reported honestly.** `git status` now has its own 10 s budget
  (`GIT_STATUS_READ_TIMEOUT_MS`) because `-uall` walks every untracked file. A timeout
  is a new `GitUnavailableReason: "timeout"`: the panel says _Git did not answer_ and
  does **not** offer _Initialize repository_ to a folder that is already a repository.
- **A failed diff read clears the previous diff.** The dialog can no longer show another
  file's content after a click that failed; the failure appears as the rail's error line.

### Site and docs

- **One-page product site.** The public site is now a single landing page (hero, features,
  screenshots, installation, FAQ); docs and release notes are still generated from
  `docs/` and served under `/docs/`.
- **Documented contract.** [`docs/architecture/source-control.md`](https://github.com/dieuluucanh/pi-desktop/blob/main/docs/architecture/source-control.md)
  records why `-uall` is required, what happens to a nested repository, how the
  untracked diff is synthesised, and why the view sorts while the engine does not.
  The user guide's Changes section describes the row actions and the timeout state.

## Known limitations

- **Unsigned builds.** Windows SmartScreen and macOS Gatekeeper warn on first launch, and
  macOS requires the System Settings approval described above. Code signing and
  notarization need an Apple Developer Program membership and a Windows certificate; both
  are backlog items, not v0.6.0.
- **macOS and Linux are beta.** **Verified structurally, not on a live machine** on
  macOS, and not re-verified by hand on a Linux desktop for this release. Windows remains
  the primary, hand-verified platform.
- **macOS updates are manual** until a stable signing identity exists (see above).
- **The first live update cycle is being proven now.** v0.5.0 was the first published
  feed; v0.6.0 is the first version an installed v0.5.0 build can update to. Windows and
  Linux AppImage are the targets; macOS stays manual.
- **Ubuntu 24.04+ dependency naming.** The `.deb` depends on `libasound2t64 | libasound2`
  to cover both the 24.04 rename and older releases; distributions with neither name fail
  the install with a dependency error.
- **AppImage updates** require the desktop to set `APPIMAGE`, which is standard for
  AppImageLauncher and most menus but not universal; the `.deb` install never
  self-updates.
- **Nested repositories stay invisible in Changes.** Deliberate, documented parity with
  VS Code; the Explorer still sees them.
- **A path beyond the 2 000-path status cap cannot be staged from the rail.** The
  truncated banner already sends the user to a terminal, and the cap is unchanged.

## Upstream

The app pins `@earendil-works/pi-coding-agent` 1.4.0 and ships Node 24 as its bundled
runtime. Pi's `SettingsManager`/`SessionManager` write non-atomically, so a crash during
Pi's own flush can truncate `settings.json` or a session JSONL; the pinned SDK cannot be
patched. All SDK contact stays in `src/host/sdk/*`, which is what keeps an upgrade to one
directory.
