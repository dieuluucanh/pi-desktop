# Pi Desktop v0.9.0

**Release date:** 2026-11-14 · **Status:** published to GitHub Releases by
`.github/workflows/release.yml` on tag `v0.9.0` · **Pi SDK:**
`@earendil-works/pi-coding-agent` 1.5.0 · **Companion extension:**
`@dieulc/workflow` ≥ 0.11.0 · **Bundled runtime:** Node 24.22.2

Pi Desktop is a standalone desktop app for the [Pi coding agent](https://pi.dev):
projects, sessions, chat, providers, models, extensions, packages, skills, themes and
settings in a UI, using the **same `~/.pi/agent` profile as terminal Pi**, so the two are
interchangeable. **Pi for Office is an optional integration**, not a built-in surface.

This is the seventh public release, a **Review Mode isolation and rendering parity**
release. Review is now its own locked mode with a visible control bar and an in-app
handoff page; transcript Markdown and extension text keep one source line per line; and a
single clipboard gesture writes to the terminal exactly once.

> **Upgrade both halves.** Review Mode isolation needs `@dieulc/workflow` **0.11.0 or
> newer**. With an older extension the desktop shows no Review badge (the extension still
> enforces its own lock); with the 0.11.0 extension and an older desktop the review runs
> without the new bar. Install the extension from the Extensions hub or with
> `pi install @dieulc/workflow@0.11.0`.

## Highlights

- **Review owns the turn.** `🔍 review`, `🔍 review — paused` and
  `🔍 review — awaiting decision` are parsed as a fourth workflow mode, not inferred from
  a working message. While Review runs, prose and `!` shell prompts are refused with a
  hint and the draft is preserved; slash commands (pause/resume/abort, `/model`,
  `/profile`, …) stay available.
- **A Review bar.** Above the working row: Pause/Abort while running, Resume/Abort while
  paused, and **Open review tab** during the handoff, which links straight to the session's
  own loopback review tab. Stop is hidden in Review — it would abort the parent run.
- **The review page is an app tab.** Desktop host processes are launched with
  `PLANNOTATOR_BROWSER=none`, so Plannotator never opens the system browser. A reused
  review URL is focused and reloaded only after its parked view exists, and the app window
  is raised. Terminal Pi keeps its normal browser behaviour, and the tab's **Open in
  browser** button remains the escape hatch.
- **One source line, one rendered line.** `remark-breaks` makes every soft newline in
  transcript Markdown a real line (matching `pi-tui`), and a shared `MultilineText`
  primitive renders extension plain text (`ctx.ui.notify`, confirm/select text, the working
  message, notification rows, toasts and the session error banner) with `white-space:
pre-wrap` instead of collapsing it. `/profile` output and the Build Complete TODO list
  keep their lines.
- **Paste happens once.** `Ctrl+V`/`Cmd+V` used to reach the shell three times: xterm ran
  the custom key handler on keydown _and_ keyup, and returning `false` did not cancel
  Chromium's own paste command. Now only the keydown of a claimed chord acts,
  `preventDefault()` cancels the browser's command, and one `paste-intake` decision point
  dedupes a native/menu paste that races the app within 200 ms. Same-source repeats (key
  repeat, two deliberate pastes) still pass.

## What changed since v0.8.2

### Review Mode is isolated

`@dieulc/workflow` 0.11.0 tracks the review as an explicit turn
(`running → paused → running → handoff → transition → idle`) and stops the reviewer
before a decision is applied. The desktop decodes the mode and phase, renders the Review
bar, refuses prose at the store, and never sends an abort from the composer's Stop button.

Cross-version behaviour is deliberate:

| Extension | Desktop | Result                                                                 |
| --------- | ------- | ---------------------------------------------------------------------- |
| 0.11.0    | 0.9.0   | Review badge, bar, locked prompts, in-app review tab                   |
| 0.11.0    | 0.8.x   | No badge; the extension still locks prompts and modes                  |
| 0.10.0    | 0.9.0   | Legacy `⏸ plan — reviewing in browser` parses as Plan, never as Review |
| 0.10.0    | 0.8.x   | Unchanged                                                              |

### Transcript and extension text keep their lines

The transcript's Markdown pipeline now includes `remark-breaks`, so a CommonMark soft
break renders as its own line; fenced/indented code keeps its newlines. Extension **plain
text** never goes through Markdown: it renders verbatim through `MultilineText`. Only
`custom_message` / `custom` entry content still uses the Markdown pipeline. Desktop
markdown chrome (bubbles, list bullets, headings, highlighted code cards and the 110 ch
measure) is unchanged.

### The terminal pastes once per gesture

Two rules — only the keydown of a claimed chord acts, and a claimed keydown cancels the
DOM default — plus a single paste writer for the chord, the toolbar button and the native
`paste` event. `src/renderer/src/terminal/paste-intake.ts` is the one decision point: an
identical text from the other source within 200 ms is the same gesture and is dropped,
while same-source repeats always pass. A real-app E2E test now pastes into the terminal and
asserts exactly one write reaches the shell.

## Install

Download from [GitHub Releases](https://github.com/dieuluucanh/pi-desktop/releases).

| Platform      | Artefacts                                                                                                            | Status  |
| ------------- | -------------------------------------------------------------------------------------------------------------------- | ------- |
| Windows (x64) | `Pi-Desktop-0.9.0-win-x64-setup.exe` (NSIS), `Pi-Desktop-0.9.0-win-x64-portable.exe`                                 | primary |
| Linux         | `Pi-Desktop-0.9.0-linux-x86_64-appimage.AppImage`, `Pi-Desktop-0.9.0-linux-amd64-deb.deb` (x64) and the `arm64` pair | beta    |
| macOS         | `Pi-Desktop-0.9.0-mac-arm64.dmg`, `Pi-Desktop-0.9.0-mac-x64.dmg` (plus the `.zip` pair used by the updater)          | beta    |

Builds are **unsigned**. Windows SmartScreen warns on first launch (**More info → Run
anyway**). macOS additionally requires an explicit approval:

1. Open the `.dmg` and drag **Pi Desktop** into `/Applications`.
2. Launch it once. macOS refuses, and there is no right-click override any more.
3. Open **System Settings → Privacy & Security**, scroll to the bottom, and choose
   **Open Anyway** for Pi Desktop.

If the bundle reports that it is **damaged** instead (usually after unzipping the `.zip`
rather than mounting the `.dmg`), clear the quarantine flag and try again:

```bash
xattr -dr com.apple.quarantine "/Applications/Pi Desktop.app"
```

On Linux, the AppImage needs FUSE (`libfuse2`, or run with `--appimage-extract-and-run`);
install the `.deb` with `sudo apt install ./…deb` rather than `dpkg -i` so the
GTK/NSS/asound dependencies resolve. The app bundles its own Node runtime: no system
Node, npm or Pi install is needed.

| ---------------- | ---------------------- | ------------------------------------------ |
| Windows          | yes, 10 s after launch | yes — download, then **Restart & install** |
| Linux (AppImage) | yes                    | yes                                        |
| macOS            | **no**                 | **no** — download the new `.dmg`           |

macOS updates stay download-only: Squirrel.Mac validates a downloaded update against the
running app's code-signing requirement, and an ad-hoc signature's requirement changes with
every build. **About & updates** says **Manual updates** and links to the Releases page.

v0.9.0 is the version an installed v0.8.2 build picks up (Windows and the Linux AppImage).
macOS stays manual.

## Known limitations in v0.9.0

Every known limitation is recorded here and in the user guide:

- **Unsigned builds** — SmartScreen/Gatekeeper warn on first launch; signing is deferred
  ([backlog](../product/backlog.md)).
- **macOS and Linux are beta** — built and structurally verified in CI, but no real macOS
  launch and no fresh Linux desktop install have been exercised by a person for this
  release. Windows is the verified target.
- **Review Mode needs `@dieulc/workflow` ≥ 0.11.0 for the desktop contract.** An older
  extension keeps its own lock but the desktop shows no Review badge or bar; the in-app
  review tab and `PLANNOTATOR_BROWSER=none` still apply. Without Plannotator, a review
  falls back to the inline decision prompt.
- **The review tab is loopback-only** — a page served somewhere else opens in the system
  browser. The bar's **Open review tab** disappears when the linked tab has been closed;
  the `/review-*` commands remain available.
- **Review Mode's manual matrix is unverified for this release** — see Verification. The
  plan's steps 16 (E2E review-handoff fixture) and 19 (manual provider matrix) are not part
  of this build.
- **macOS updates are manual** — an ad-hoc signature cannot satisfy Squirrel.Mac, so the
  app links to the release instead of offering an in-place install.
- **The updater** is verified against its policy and a fake port, not a live GitHub Release
  feed.
- **Upstream** SDK/provider changes can affect extensions and model behaviour; this release
  pins `@earendil-works/pi-coding-agent` 1.5.0 and requires the companion workflow
  extension 0.11.0 for Review Mode.
- **Verified structurally, not on a live machine** — the Linux and macOS artefacts are
  built and structurally checked in CI; no person has launched every artefact on real
  hardware for this release.
- **The terminal is local only** — one shell per tab, no SSH/remote session, no tmux
  control mode and no docked split panel; it does not spawn in an untrusted project until
  you grant trust. The Linux native backend is built for **glibc 2.31 /
  `GLIBCXX_3.4.28`**.
- **Transcript find cannot mark across a soft break** — a query spanning a line break is
  counted by the matcher but one `<mark>` cannot span the rendered `<br>`; copy still uses
  the raw message text.
- **Informational notifications are hidden by default** — enable **Informational messages**
  in Settings → Notifications to show them in the bell and transcript. Hidden rows are
  never lost: **Show hidden (N)** reveals them.
