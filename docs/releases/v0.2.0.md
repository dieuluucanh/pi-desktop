# Pi Desktop v0.2.0

**Release date:** 2026-10-27 · **Status:** development build, built locally (not
published to GitHub Releases) · **Pi SDK:** `@earendil-works/pi-coding-agent`
1.4.0 · **Bundled runtime:** Node 24

Pi Desktop is a standalone desktop app for the [Pi coding agent](https://pi.dev):
projects, sessions, chat, providers, models, extensions, packages, skills, themes
and settings in a UI, using the **same `~/.pi/agent` profile as terminal Pi**, so
the two are interchangeable. **Pi for Office is an optional integration**, not a
built-in surface.

This is the second tagged release. It upgrades the app from the 0.85.1 SDK to
**Pi 1.4.0** and closes the session-UX gap against terminal Pi — transcript,
composer, commands, session browser, tree and keybindings — on top of the model
scope, provider, packaging and branding fixes gathered since v0.1.0.

## Install

The artefacts below are produced locally under `release/`. They are equivalent
in layout to the v0.1.0 assets, with the version and SDK updated.

| Platform | Artefacts                                                                                                            | Status    |
| -------- | -------------------------------------------------------------------------------------------------------------------- | --------- |
| Windows  | `Pi-Desktop-0.2.0-win-x64-setup.exe` (NSIS), `Pi-Desktop-0.2.0-win-x64-portable.exe`                                 | primary   |
| Linux    | `Pi-Desktop-0.2.0-linux-x86_64-appimage.AppImage`, `Pi-Desktop-0.2.0-linux-amd64-deb.deb` (x64) and the `arm64` pair | beta      |
| macOS    | `.dmg`, `.zip` (arm64 + x64)                                                                                         | not built |

Builds are **unsigned**. Windows SmartScreen and macOS Gatekeeper warn on first
launch; the guide has the per-platform steps (including the Linux FUSE and
`apt install ./…deb` notes). The app needs no pre-installed Node and no
pre-existing Pi — the runtime is bundled.

**Distribution status.** No GitHub Release was created for this build, so the
`electron-updater` feed (`latest.yml`, `latest-linux*.yml`) has not been
advanced. Installed v0.1.0 builds will therefore not see v0.2.0 until the
artefacts are uploaded to a release with the usual tag.

## What changed since v0.1.0

### Session UX parity with terminal Pi 1.4.0

- **SDK 1.4.0.** `pi-agent-core`, `pi-ai`, `pi-coding-agent` and `pi-tui` are
  pinned together at 1.4.0, the same generation terminal Pi runs.
- **Transcript correctness.** Turn plumbing (`agent_start`, `agent_end`,
  `agent_settled`, `turn_start`, `turn_end`, `session_info_changed`) is silent
  state instead of visible notices; every resume role (`compactionSummary`,
  `branchSummary`, `bashExecution`, `toolResult`, `custom*`) maps to the right
  row; tool calls render once, in content order, with previews; aborted tools are
  swept out of "running…"; stop reasons (aborted/error/length) are explained.
- **Streaming and navigation.** The viewport follows growing content while
  pinned, with a jump-to-latest pill and `Ctrl+End`; transcript find (`Ctrl+F`)
  marks matches and steps through them.
- **Bash mode.** `!` and `!!` run through the host (`executeBash`), stream into
  the transcript and keep or exclude context as terminal does; no more prose sent
  to the model.
- **Run control.** Retry countdown with cancel, compaction and branch-summary
  rows with cancel, queued prompts as pending rows with `Alt+Up` restore and the
  live queue modes.
- **Composer.** Paste markers with a content-lost hint, `Ctrl+G` expanded
  editor, `Ctrl+X` copy-last, host-tagged command prompts collapsed by default
  (row toggle, `Ctrl+O` or `prefs.showExpandedPrompts`), and Enter now clears the
  draft at submit.
- **Commands.** `/copy`, `/session`, `/clone` (leaf-fork fallback), `/export
jsonl`, `/import`, `/changelog`, `/hotkeys`, `/quit`, `/share` (secret gist)
  and `/bug` (local redacted zip, no upload). Extension commands complete and run
  their argument grammar like terminal Pi.
- **Session browser and tree.** Scope tabs, sort cycle, named-only/path toggles,
  regex/phrase search; tree filters, fold, label timestamps and the
  branch-summary prompt.
- **Rendering.** KaTeX and lazy Mermaid (off / final / streaming).
- **Keybindings.** Pi actions plus a desktop action registry, conflict
  detection and a key-capture UI.

### Models, settings and providers

- **Model scope is persisted.** Every model/thinking pick is written to Pi's
  config, the picker stars Pi's scope rather than app favourites, and
  `/scoped-models` reports the effective scope.
- **Live model following.** Picker- and extension-driven model changes reach the
  session header and composer immediately; a stale main model is detected.
- **Project settings toggle.** One control for the per-project settings override,
  with external-edit detection kept intact.
- **Gateway model ids.** Custom gateways accept real model ids and merge them on
  save instead of rejecting unknown ids.

### Composer, workflow and host fixes

- **Workflow mode.** The workflow extension's mode border, badge and footer with
  `Tab` cycling, including the startup `Tab` race and the Plan label.
- **Renderer polish.** Composer, transcript, session header and extension UI
  refinements.
- **Stale host bundle recycling.** A changed host bundle is detected and
  restarted, so completion and commands stop running old code.
- **Truthful session waking.** Ready sessions wake correctly and renderer-less
  entries stay out of the tab strip.
- **Branding.** App icons, window/dock marks and identity.
- **Packaging.** The Linux installers (x64 and arm64) and the packaged host were
  fixed, and the v0.1.0 packaging fixes are carried forward.

The detailed chat/composer contract and its enforcement tests live in
[`../architecture/session-parity.md`](../architecture/session-parity.md). The
feature-by-feature comparison with terminal Pi is
[`../product/parity.md`](../product/parity.md).

## Known limitations

Everything below is a real, user-visible limitation of v0.2.0, not a claim that
the feature is missing. The automated suite covers the logic; the items marked
"unverified on a real machine" need hardware/providers the build host does not
have.

### Platform and distribution

- **Unsigned builds.** SmartScreen/Gatekeeper warnings on first launch; signing
  and notarization are deferred ([backlog](../product/backlog.md)).
- **macOS and Linux are beta.** The Linux `AppImage` and `.deb` (x64 + arm64)
  were built on Ubuntu 26.04 under WSL2 on the same Windows machine and verified
  structurally (control metadata, contents, the per-architecture bundled Node
  runtime, packaged shims, and the x64 packaged host reporting 1.4.0). They have
  not been installed or run on a Linux desktop, and the arm64 binaries cannot be
  executed on the x64 build host at all. macOS was not built for this release.
  Windows remains the verified target.
- **The Windows installer builds, but has not been installed on a clean VM.**
  `package:win` produces both artefacts with URL-safe, target-distinct names;
  the clean-VM install and first session remain the manual acceptance gate.
- **The updater is unchanged and was not exercised against a live feed.** This
  build published no GitHub Release, so no download → restart → install round
  trip happened.

### Verified structurally, not on a live machine

- **Provider sign-in** (OAuth device/code flows) against real providers; the
  request/response plumbing and redaction are unit-tested.
- **Extension UI fidelity**: a real extension's `notify`/`status`/`widget`,
  `ctx.ui.custom()` overlays, footers/headers/custom editors and custom
  `renderCall`/`renderResult` renderers in the packaged app.
- **Office**: the wizard acceptance row (detect → install → sideload → verify)
  and the bridge end to end (a real pane attached, `document:"active"` following
  focus, `#name` routing). Automated tests use scripted `/health` and fake
  runners.
- **Plannotator review round trip** and the in-app web tab.
- **Web-tab isolation on a loaded page**: creation flags are asserted, not a real
  page proving `window.pi` is absent.
- **Reliability**: crash/timeout banners against a real wedged host, safe mode
  against a genuinely broken extension, and the diagnostics bundle from a real
  run with real credentials.
- **Performance**: 60 fps is asserted structurally, and the RSS/restart budgets
  use injected samples.
- **The 1.4.0 session surface against a live model**: the reducer, hydration,
  tool pairing and command paths are fixture-tested; a full live session with
  every new command (`/share`, `/import`, `/export jsonl`, `/bug`) has not been
  walked end to end.
- **Keybinding capture UI** on a real keyboard layout beyond the tested chords.

### Upstream (not fixable in this app)

- **Pi's own writers are not crash-atomic.** `SettingsManager` writes
  `settings.json` with `writeFileSync`, and `SessionManager` appends/rewrites
  session JSONL with `appendFileSync`/`writeFileSync`. The app cannot patch the
  pinned SDK, so a crash _during Pi's own flush_ can still truncate those files.
  The app's own profile writes are atomic and `fsync` before the rename.
- **MCP is parity, not a built-in.** Like terminal Pi, MCP is reached through an
  installed extension; there is no first-party bridge
  ([backlog](../product/backlog.md)).
- **Backups cover `settings.json`**, not every profile file. `models.json`,
  `keybindings.json` and imported themes are written atomically but are not
  backed up before the first app write.
- **Phase G (update channels) is deferred.** The app updates its own code only;
  the Pi runtime and installed extensions have no update channel yet.

### Deliberately deferred

See [`../product/backlog.md`](../product/backlog.md) for the full list with
reasons: in-app terminal tab, native Plan/Review workspace, SQLite session
index/search, i18n, git worktrees, first-party MCP bridge, multi-window/scheduled
tasks/cloud sessions, code signing, and the external-editor launcher.

## Data, privacy and updates

- The app shares `~/.pi/agent` by default (settings, `auth.json`, sessions,
  extensions, packages). The onboarding profile step can keep a private profile
  under `userData` instead; the choice applies on the next launch.
- **Telemetry is off unless explicitly enabled.** The app sets
  `PI_TELEMETRY=0` for every host unless the preference is on, and never rewrites
  the shared `settings.json` for it.
- `auth.json` is Pi's and written `0600`; no IPC channel returns credential
  material, and the diagnostics bundle is redacted.
- Writes to the profile go through Pi's SDK managers or the app's atomic helpers
  (temp file → `fsync` → rename). A malformed `settings.json`, `auth.json` or
  `app-state.json` is reported and left untouched, never repaired silently.

## Verification status

- **Automated (green on the release commit):** `format:check`, `typecheck`,
  `lint` (0 errors), `test` (unit + renderer + packaging), `build`,
  `runtime:verify`, `office:manifest:check` and the packaging config guard.
- **Windows packaging:** the Windows targets were packaged with
  `electron-builder --win --publish never` after `npm run build` and
  `npm run runtime:verify`, producing `Pi-Desktop-0.2.0-win-x64-setup.exe` and
  `Pi-Desktop-0.2.0-win-x64-portable.exe`; `latest.yml` names the setup file.
- **Linux packaging:** in WSL2 (Ubuntu 26.04), `runtime:verify` passed 11/11 and
  `electron-builder --linux` produced the x64 and arm64 AppImage and `.deb`
  artefacts, one architecture per run so each package carries only its own
  bundled Node runtime and packaged shims. The `.deb` control metadata (name,
  version, architecture, maintainer, depends), the file list (bundled runtime,
  host bundle outside the asar, `.desktop` entry) and the AppImage payload were
  inspected; the x64 packaged `pi` shim runs the host and reports `1.4.0`.
  `latest-linux.yml` and `latest-linux-arm64.yml` name their own artefacts.
- **Manual (still the release gate):** the clean-machine install and first
  session with real providers (and a real Office install for the integration),
  on Windows and, for the beta, a real Linux desktop.
