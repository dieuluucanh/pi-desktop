# Pi Desktop v0.7.2

**Release date:** 2026-11-07 · **Status:** draft only — never published. The v0.7.2
run built and uploaded Windows and macOS, but its Linux jobs failed the artefact guard
(which still demanded both architectures per matrix job), so the release stayed a
draft. The tag stays where it is and the first published 0.7 build is
[`v0.7.3`](v0.7.3.md) · **Pi SDK:**
`@earendil-works/pi-coding-agent` 1.4.0 · **Bundled runtime:** Node 24.22.2

Pi Desktop is a standalone desktop app for the [Pi coding agent](https://pi.dev):
projects, sessions, chat, providers, models, extensions, packages, skills, themes and
settings in a UI, using the **same `~/.pi/agent` profile as terminal Pi**, so the two are
interchangeable. **Pi for Office is an optional integration**, not a built-in surface.

This is the third public release. The headline is the **integrated terminal**: a real
PTY-backed shell tab that lives in the same strip and pane grid as sessions, with shell
profiles, a Settings card and a theme that follows the app. The rest of the release is
reliability work on the surfaces that made people wait or move without asking — sessions
that opened twice, background hosts that stole the active tab, a session browser that
looked empty on large profiles, and transcripts that lost their syntax colours.

### Why there is a v0.7.2

Two tag runs stopped before a single installer was published; both were release-tooling
defects, not product regressions, and neither tag was moved.

1. **v0.7.0** failed in `npm run runtime:verify` on Linux and macOS. The check's own
   `runBare()` helper stripped `PATH` down to the bundled runtime and then spawned the
   **bare name `sh`**, which that PATH does not contain. `spawnSync` returned
   `status: null` without running anything, so `node`, `npm`, `npx` and `pi` all
   "failed" although the bundled runtime was fine. Windows was unaffected because
   `runBare()` spawns `%ComSpec%` by absolute path. Fixed by spawning `/bin/sh`.
2. **v0.7.1** then failed while **packaging Linux**. `electron-builder.yml` pinned
   `arch: [x64, arm64]` on the AppImage and deb targets, and that list overrides the
   matrix job's `--x64` / `--arm64` flag. Each Linux job therefore packaged both
   architectures and `afterPack` failed looking for the runtime it had deliberately not
   fetched (`no bundled runtime for linux-arm64`). The targets no longer pin an arch;
   the matrix's CLI flag decides, and `npm run package:linux` passes both flags for a
   local dual-arch build. `tests/packaging/builder-config.test.ts` now guards that.

This patch is the first published build of the 0.7 line and carries everything below.

## Install

Download from [GitHub Releases](https://github.com/dieuluucanh/pi-desktop/releases).

| Platform      | Artefacts                                                                                                            | Status  |
| ------------- | -------------------------------------------------------------------------------------------------------------------- | ------- |
| Windows (x64) | `Pi-Desktop-0.7.2-win-x64-setup.exe` (NSIS), `Pi-Desktop-0.7.2-win-x64-portable.exe`                                 | primary |
| Linux         | `Pi-Desktop-0.7.2-linux-x86_64-appimage.AppImage`, `Pi-Desktop-0.7.2-linux-amd64-deb.deb` (x64) and the `arm64` pair | beta    |
| macOS         | `Pi-Desktop-0.7.2-mac-arm64.dmg`, `Pi-Desktop-0.7.2-mac-x64.dmg` (plus the `.zip` pair used by the updater)          | beta    |

Builds are **unsigned**. Windows SmartScreen warns on first launch (**More info → Run
anyway**). macOS additionally requires an explicit approval:

1. Open the `.dmg` and drag **Pi Desktop** into `/Applications`.
2. Launch it once. macOS refuses, and there is no right-click override any more.
3. Open **System Settings → Privacy & Security**, scroll to the bottom, and choose
   **Open Anyway** for Pi Desktop.

If the bundle reports that it is **damaged** instead (usually after unzipping the `.zip`
rather than mounting the `.dmg`), clear the quarantine flag and try again:

```bash
xattr -dr com.apple.quarantine "/Applications/Pi Desktop.app"
```

On Linux, the AppImage needs FUSE (`libfuse2`, or run with `--appimage-extract-and-run`);
install the `.deb` with `sudo apt install ./…deb` rather than `dpkg -i` so the
GTK/NSS/asound dependencies resolve. The app bundles its own Node runtime: no system
Node, npm or Pi install is needed.

## What changed since v0.6.0

### Integrated terminal

A `terminal` tab is a real shell, not a Pi session: no agent, no model, no transcript,
and it is never a host-backed tab. The composer's `!`/`!!` stays the "the agent should
see this" runner; the terminal is the "I am driving a shell" surface.

- **PTY-backed, with its own host process.** A tab spawns `node-pty` under the bundled
  Node through a dedicated, SDK-free terminal host (`out/host/terminal.mjs`), speaking
  JSONL frames over stdio. PTY output is batched (~16 ms / 32 KiB) and carried as bytes
  written straight into xterm, so xterm owns the UTF-8 decoder and a multi-byte
  character split across a chunk is safe. Credit-based backpressure pauses the PTY at
  1 MiB unacked and resumes at 256 KiB, and a 256 KiB replay ring makes a renderer
  reload duplicate-free.
- **Shell profiles, detected in main.** PowerShell 7 → Windows PowerShell → Command
  Prompt, plus Git Bash (both conventional layouts) and WSL distributions on Windows;
  `$SHELL` and the POSIX fallbacks elsewhere. WSL's UTF-16LE listing is decoded and
  `C:\x` maps to `/mnt/c/x` for `--cd`. The renderer never supplies a shell path, argv
  or environment — it sends a validated profile id and main builds the spawn spec
  immediately before spawning.
- **Trust is still a gate.** A terminal in an untrusted project does not spawn; the tab
  shows the trust notice and the Retry button passes the session grant. `never` refuses.
- **Settings → Terminal.** Default profile (Auto, any detected shell, or a validated
  absolute custom path), font size and family with a live preview, cursor style and
  blink, scrollback, copy-on-selection, a visual bell and (on macOS) Option-as-Meta.
  Live terminals pick up changes without recreating the shell or losing scrollback.
  The one-off profile from the strip chevron is stored on the tab record, so restore
  keeps the shell it was opened with while a new default only affects new terminals.
- **The strip's New Terminal control is one joined chip.** The left segment opens the
  saved default; the right chevron opens the one-off profile menu. The order is
  New session → New terminal → Grid layout, and **New Terminal** / **Toggle Terminal**
  are also menu commands.
- **Pane plumbing that survives tab switches.** xterm instances are pooled and their
  containers are _moved_ on unmount, never disposed, so scrollback and alt-screen state
  survive a tab switch or a grid change. The pool keeps a definite height chain so
  FitAddon measures the pane, not the terminal's own content (the old failure mode
  painted 24 rows and stopped).
- **Shell keys belong to the shell.** `src/shared/terminal-keys.ts` is a pure policy:
  Ctrl+C/N/P/W/B/G and the rest go to the PTY; only copy/paste, find, clear, terminal
  new/toggle/close, tab cycling, the palette and font zoom are app actions. On
  Windows/Linux main disables menu accelerators while a terminal has focus so a menu
  chord cannot steal them.
- **Packaging.** `node-pty` 1.x is N-API, so the prebuilds work under both the bundled
  Node and Electron; `electron-builder.yml` sets `npmRebuild: false` and `afterPack`
  prunes the ~64 MB of prebuilds to the target platform/arch. Linux releases are now a
  matrix: x64 on `ubuntu-latest`, arm64 on `ubuntu-24.04-arm`, because Linux has no
  upstream `node-pty` prebuild and node-gyp must compile on the target.

### Sessions that no longer move you

- **One tab per session file.** A session JSONL may have exactly one live manager, but
  repeat clicks from the browser could spawn several multi-hundred-MB hosts on one
  file. Tabs are now keyed by a single identity rule (unified separators, Windows case
  fold); a second open activates the existing tab, and duplicate tabs persisted by
  older builds are collapsed on restore.
- **The browser dismisses on the pick.** Choosing a session closes the dialog
  immediately instead of after the host has loaded, the focused tab's session is marked
  **Current** (badge + `aria-current`), and a second resume or **Continue** while one is
  in flight is ignored instead of queueing another host.
- **Background work never reassigns the active tab.** Starting a host, waking a
  background session, recycling a host or a model fallback no longer moves the user.
  The session service publishes monotonic `revision`/`selectionSeq`, fences transcript
  writes on a session epoch, coalesces opens per generation and splits `ensure` (wake
  without selecting) from `activate`.
- **A stop is a typed error, not a 30-second wait.** Stopping or replacing a host
  drains in-flight requests with `HostStoppedError`. RSS recycling needs two
  consecutive over-budget samples plus a startup grace window and never touches the
  active/visible pane — it warns instead. Per-tab host logs rotate (`<id>.1-.3.log`), so
  a restart loop keeps the evidence that explains it.
- **A slow open says so.** The starting banner names the phase, counts seconds and
  offers **Cancel**; Diagnostics reports the last open's phases (`trust`, `services`,
  `scope`, `session`, `bind`, `reconcile`, `total`) and the supervisor's `bootMs`
  against explicit budgets.
- **Extension dialogs and web tabs respect the focused window.** A new
  `prefs.dialogs.autoFocus` (with window-focus, composer and streaming guards) stops a
  background web tab or extension dialog from stealing the active tab.
- **One host per session.** The registry refuses a second start for a live session id,
  joins concurrent control-host starts through one in-flight promise, adopts a host that
  won the supervisor race (`host_duplicate_start`), settles `ready()` on stop and resets
  the crash budget on a manual restart. A caller race can no longer strand a pinned,
  unreachable child.
- **A saved model that disappeared is reported.** The picker surfaces resolver warnings
  instead of silently swapping a model, and the scope rule refuses colon-bearing ids
  rather than writing a pattern Pi cannot parse.

### The session browser works on large profiles

`/resume` used to show an empty browser on a large profile: `session.list` returned the
raw session records — including every message's text — crossed the 1 MiB blob-spill
threshold, and the renderer read the missing `sessions` field as "no sessions".

- The **control host** now projects `session.list` itself (filter, sort, limit, epoch-ms
  timestamps) and searches the **full transcript**; a session host no longer answers it,
  so a request against a session tab fails instead of listing one project.
- Listings are bounded under 768 KiB and paged as `{ sessions, total, matched, truncated,
error }`; the browser shows "Showing N of M", uses a 150 ms debounce with a
  stale-response guard, and distinguishes a query error from a transport error.
- `host.blobs.read` now returns UTF-8-safe byte-range chunks (2 MiB per frame), so any
  spilled response can be read back; every `sessions.request` resolves its blob once.
- Unknown timestamps render as "—" rather than 1970, and project paths compare
  case-insensitively on Windows, matching Pi's own cwd rule.
- Transcript hydration reports its first failure per tab instead of looking like an
  empty session.
- **Copy Path** now reports success or failure where the user clicked, and lands in tab
  menus and session-browser rows. The session strip gained a **History** button next to
  **New terminal**.

### Chat, composer and transcript

- **Prompt history keeps your draft.** `Up`/`Down` across previously sent prompts stashes
  the draft (text _and_ caret) on entry and restores it — including an intentionally
  empty draft — with no wraparound and stale-index clamping. History is seeded from the
  hydrated transcript's user messages plus prompts sent this run, and re-seeded on
  hydrate and branch switch.
- **Inline code spans are inline again.** `react-markdown` 10 calls the same `code`
  renderer for an inline span and a `pre > code` block; the block body is now read from
  the AST, `pre` owns Mermaid and `CodeBlock`, and a span renders the token-driven pill
  instead of a block-level `<pre>` inside its sentence.
- **A readable measure.** The transcript content column is capped at 110ch on both the
  plain and virtualized paths; the scrollbar, find bar and jump chrome stay pane-wide.
- **Syntax colours survive re-renders.** A bounded token cache provides a synchronous
  warm path, and `Markdown` is memoized with `streaming` in context, so a re-render no
  longer remounts code blocks and drops their highlighting.
- **`!` completion belongs to extensions.** The built-in shell-path completion source is
  gone (matching terminal Pi): a `!`/`!!` line yields no local suggestions, Tab can reach
  a registered shortcut, and the extension chain is still called so a provider can opt
  in. Shell detection lives in one module shared by the composer, completion stack and
  send path, and the idle placeholder advertises `! shell`.

### Runtime, development and the site

- **Node 24.22.2** is the pinned runtime, with refreshed archive checksums and npm
  payload digests. The fetch script maps Windows targets to the archive names nodejs.org
  actually publishes, samples the npm payload only from a matching on-disk runtime, and
  writes the refreshed lock so a stale tree cannot stamp an old digest onto a new
  version.
- **`node.cmd` is retired.** The selected Node's directory goes on the host `PATH`, so
  `cmd`, PowerShell and `spawn("node")` get a real `node.exe`; a project tool that
  starts node through `cmd` (turbo → `pnpm.cmd`) no longer dies with "The system cannot
  find the path specified". The remaining `.cmd` shims locate themselves on `PATH`.
- **The dev server has its own port.** The renderer dev server binds
  `127.0.0.1:5273` with `strictPort` (validated `PI_DESKTOP_RENDERER_PORT` override), so
  the app can no longer take Vite's 5173, silently drift to 5174, or answer a project
  URL. `npm run doctor` reports the address and whether it is free.
- **`npm run dev` stops whole child trees** (`taskkill /T` on Windows), so a dead
  `cmd.exe` cannot orphan Vite/Electron and hold the port.
- **The site never presents an older release as latest.** In the window between the
  Pages deploy and the release publish, the installer buttons keep the newest installer
  that actually exists and the status line says `Latest published v<old> · v<new> is
publishing`; that answer is not cached, so the next load after publish switches.
- Site polish: inline links keep their separating space in every emitted page, landing
  rows align with subgrid, the logo stays inside the nav bar, search moved beside the
  theme controls, and the theme icons were replaced.

_packaged_ macOS or Linux build.

## Known limitations

- **Unsigned builds.** Windows SmartScreen and macOS Gatekeeper warn on first launch, and
  macOS requires the System Settings approval described above. Code signing and
  notarization need an Apple Developer Program membership and a Windows certificate; both
  are backlog items, not v0.7.0.
- **macOS and Linux are beta.** **Verified structurally, not on a live machine** on
  macOS, and not re-verified by hand on a Linux desktop for this release. Windows remains
  the primary, hand-verified platform.
- **macOS updates are manual** until a stable signing identity exists (see above).
- **The terminal needs a real PTY.** It is a local shell only: there is no remote/SSH
  session, no tmux control mode, no session recording and no docked split panel. Terminals
  in an untrusted project do not spawn until you grant trust.
- **Linux arm64 needs node-gyp at release time.** There is no upstream `node-pty`
  prebuild for Linux, so the arm64 job compiles on an arm64 runner. A self-built package
  from a different architecture is not supported by the prune.
- **One terminal per tab.** A terminal tab holds one shell; opening a second shell means
  a second tab. Ambiguous-width glyphs and custom glyph protocols (for example image
  protocols) are not exercised beyond xterm's own Unicode 11 addon.
- **Ubuntu 24.04+ dependency naming.** The `.deb` depends on `libasound2t64 | libasound2`
  to cover both the 24.04 rename and older releases; distributions with neither name fail
  the install with a dependency error.
- **AppImage updates** require the desktop to set `APPIMAGE`, which is standard for
  AppImageLauncher and most menus but not universal; the `.deb` install never
  self-updates.
- **Nested repositories stay invisible in Changes.** Deliberate, documented parity with
  VS Code; the Explorer still sees them.
- **A path beyond the 2 000-path status cap cannot be staged from the rail.** The
  truncated banner already sends the user to a terminal, and the cap is unchanged.
- **i18n, MCP and multi-window** remain deferred backlog, as recorded in
  [`product/backlog.md`](../product/backlog.md).

## Upstream

The app pins `@earendil-works/pi-coding-agent` 1.4.0 and ships Node 24.22.2 as its
bundled runtime. Pi's `SettingsManager`/`SessionManager` write non-atomically, so a crash
during Pi's own flush can truncate `settings.json` or a session JSONL; the pinned SDK
cannot be patched. All SDK contact stays in `src/host/sdk/*`, which is what keeps an
upgrade to one directory. The terminal host deliberately imports no SDK code and is a
separate build input.
