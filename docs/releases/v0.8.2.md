# Pi Desktop v0.8.2

**Release date:** 2026-11-10 · **Status:** published to GitHub Releases by
`.github/workflows/release.yml` on tag `v0.8.2` · **Pi SDK:**
`@earendil-works/pi-coding-agent` 1.5.0 · **Bundled runtime:** Node 24.22.2

Pi Desktop is a standalone desktop app for the [Pi coding agent](https://pi.dev):
projects, sessions, chat, providers, models, extensions, packages, skills, themes and
settings in a UI, using the **same `~/.pi/agent` profile as terminal Pi**, so the two are
interchangeable. **Pi for Office is an optional integration**, not a built-in surface.

This is the sixth public release, a **Review Mode and provider patch**. It upgrades the
bundled Pi SDK to 1.5.0 and fixes the handoff between Plan Mode, Review Mode and
Plannotator: manual `/review` is visible and pausable, every later review round reopens the
current plan, and a pending browser review survives a reload (`reload`/`resume`/`fork`).
The companion `@dieulc/workflow` 0.10.0 release adds provider recovery, chunked plan
rewrites and durable handoff correlation. The Command Code provider now has a stream probe
and a doctor report.

## Highlights

- **Manual `/review` is first-class.** An idle tab now shows `🔍 Reviewing plan…`, the
  footer's live review line, and the hint `ESC to pause · /review-pause, /review-abort`.
  Escape pauses instead of being ignored; `/review-resume` and `/review-abort` work.
- **Round 2+ always hands off.** A new round or manual review supersedes an older pending
  browser gate, stale browser decisions are discarded, and the complete review correlation
  is persisted. Plannotator reopens with the reviewed plan.
- **Reload recovery.** After `reload`/`resume`/`fork`, the extension asks Plannotator
  `review-status`: pending keeps a matching gate, completed applies the decision, and
  missing/changed clears with a reason.
- **Review tabs are in front.** A notification review URL opens and focuses its web tab;
  an existing same-URL tab is reloaded before focus. Tool-result localhost URLs stay in
  the background.
- **Provider resilience.** SDK 1.5.0, the Command Code stream probe/doctor, and the
  `@dieulc/workflow` 0.10.0 provider fallback/chunked submission path reduce unreviewed
  handoffs on long gateway streams. `pi-commandcode-provider` is recommended in the
  Extensions hub.
- **Escape parity.** Extension input handlers receive Escape before the app stops a run.

## Install

Download from [GitHub Releases](https://github.com/dieuluucanh/pi-desktop/releases).

| Platform      | Artefacts                                                                                                            | Status  |
| ------------- | -------------------------------------------------------------------------------------------------------------------- | ------- |
| Windows (x64) | `Pi-Desktop-0.8.2-win-x64-setup.exe` (NSIS), `Pi-Desktop-0.8.2-win-x64-portable.exe`                                 | primary |
| Linux         | `Pi-Desktop-0.8.2-linux-x86_64-appimage.AppImage`, `Pi-Desktop-0.8.2-linux-amd64-deb.deb` (x64) and the `arm64` pair | beta    |
| macOS         | `Pi-Desktop-0.8.2-mac-arm64.dmg`, `Pi-Desktop-0.8.2-mac-x64.dmg` (plus the `.zip` pair used by the updater)          | beta    |

Builds are **unsigned**. Windows SmartScreen warns on first launch (**More info → Run
anyway**). macOS additionally requires an explicit approval:

1. Open the `.dmg` and drag **Pi Desktop** into `/Applications`.
2. Launch it once. macOS refuses, and there is no right-click override any more.
3. Open **System Settings → Privacy & Security**, scroll to the bottom, and choose
   **Open Anyway** for Pi Desktop.

If the bundle reports that it is **damaged** instead (usually after unzipping the `.zip`
rather than mounting the `.dmg`), clear the quarantine flag and try again:

```bash
xattr -dr com.apple.quarantine "/Applications/Pi Desktop.app"
```

On Linux, the AppImage needs FUSE (`libfuse2`, or run with `--appimage-extract-and-run`);
install the `.deb` with `sudo apt install ./…deb` rather than `dpkg -i` so the
GTK/NSS/asound dependencies resolve. The app bundles its own Node runtime: no system
Node, npm or Pi install is needed.

| Windows          | yes, 10 s after launch | yes — download, then **Restart & install** |
| Linux (AppImage) | yes                    | yes                                        |

macOS updates stay download-only: Squirrel.Mac validates a downloaded update against the
running app's code-signing requirement, and an ad-hoc signature's requirement changes with
every build. **About & updates** says **Manual updates** and links to the Releases page.

## Known limitations in v0.8.2

Every known limitation is recorded here and in the user guide:

- **Unsigned builds** — SmartScreen/Gatekeeper warn on first launch; signing is deferred
  ([backlog](../product/backlog.md)).
- **macOS and Linux are beta** — built and structurally verified in CI, but no real macOS
  launch and no fresh Linux desktop install have been exercised by a person for this
  release. Windows is the verified target.
- **macOS updates are manual** — an ad-hoc signature cannot satisfy Squirrel.Mac, so the
  app links to the release instead of offering an in-place install.
- **The updater** is verified against its policy and a fake port, not a live GitHub Release
  feed.
- **Upstream** SDK/provider changes can affect extensions and model behaviour; this release
  pins `@earendil-works/pi-coding-agent` 1.5.0 and the companion workflow extension 0.10.0.
- **Verified structurally, not on a live machine** — the Linux and macOS artefacts are
  built and structurally checked in CI; no person has launched every artefact on real
  hardware for this release.
- **The terminal is local only** — one shell per tab, no SSH/remote session, no tmux
  control mode and no docked split panel; it does not spawn in an untrusted project until
  you grant trust. The Linux native backend is built for **glibc 2.31 /
  `GLIBCXX_3.4.28`**.
- **Informational notifications are hidden by default** — enable **Informational messages**
  in Settings → Notifications to show them in the bell and transcript. Hidden rows are
  never lost: **Show hidden (N)** reveals them.
- **Review Mode needs Plannotator for the browser handoff** — without it, automatic review
  falls back to the inline decision prompt; manual `/review` reports the reviewed plan path
  instead of opening a browser review.
