**Release date:** 2026-11-03 · **Status:** development build, built locally (not
published to GitHub Releases) · **Pi SDK:** `@earendil-works/pi-coding-agent`
1.4.0 · **Bundled runtime:** Node 24

Pi Desktop is a standalone desktop app for the [Pi coding agent](https://pi.dev):
projects, sessions, chat, providers, models, extensions, packages, skills, themes
and settings in a UI, using the **same `~/.pi/agent` profile as terminal Pi**, so
the two are interchangeable. **Pi for Office is an optional integration**, not a
built-in surface.

This is the fourth tagged release. It keeps the 1.4.0 SDK pin and the profile
contract from v0.3.0 and turns the app into a small workbench: a **file explorer**
as the first menu in the right rail, **CodeMirror editor tabs** in their own row
under the sessions, **project-wide file search**, **drag-to-chat mentions**,
pinned and kind-scoped tab actions, **one-click default projects**, and an honest
update surface. It also replaces the old tab/host caps with a **memory-derived
live-host budget**, so session records are unlimited while the number of running
Pi hosts stays bounded.

## Install

The artefacts below are produced locally under `release/`. They are equivalent
in layout to the v0.3.0 assets, with the version updated.

| Platform | Artefacts                                                                                                            | Status    |
| -------- | -------------------------------------------------------------------------------------------------------------------- | --------- |
| Windows  | `Pi-Desktop-0.4.0-win-x64-setup.exe` (NSIS), `Pi-Desktop-0.4.0-win-x64-portable.exe`                                 | primary   |
| Linux    | `Pi-Desktop-0.4.0-linux-x86_64-appimage.AppImage`, `Pi-Desktop-0.4.0-linux-amd64-deb.deb` (x64) and the `arm64` pair | beta      |
| macOS    | `.dmg`, `.zip` (arm64 + x64)                                                                                         | not built |

Builds are **unsigned**. Windows SmartScreen and macOS Gatekeeper warn on first
launch; the guide has the per-platform steps (including the Linux FUSE and
`apt install ./…deb` notes). The app needs no pre-installed Node and no
pre-existing Pi — the runtime is bundled.

**Distribution status.** No GitHub Release is created for this build, so the
`electron-updater` feed (`latest.yml`, `latest-linux*.yml`) has not been
advanced. Installed v0.3.0 builds will therefore not see v0.4.0 until the
artefacts are uploaded to a release with the usual tag. Locally packaged
installers are stamped `local` in `resources/build-info.json` and do not run
automatic update checks; a manual check reports the neutral “No published release
was found for this build” state, never a failure banner.

## What changed since v0.3.0

### File explorer

- **A new first menu in the right rail.** The tree loads one directory at a
  time, shows file-type icons, greys hidden files and dims git-ignored files,
  and has toolbar toggles for either (both flags reach the backend, so hidden
  and ignored folders are genuinely searchable).
- **Project-wide search.** The search box replaces the tree with a flat ranked
  result list while a query is active. It searches the whole project's file
  list — including folders that were never expanded — and matches every
  whitespace-separated term against the relative path, ranking basename matches
  above directory matches. Typing is debounced (180 ms) with a per-project
  request id, so a stale response can never overwrite a newer query. An `x`
  button and Escape clear it; truncation is reported in the footer instead of
  pretending the list is complete.
- **File actions.** New file, new folder, rename, delete to the OS recycle bin,
  Copy Path and Copy Relative Path, plus Reveal in File Manager and Refresh.
  Names are validated in the renderer and again in main.
- **Quick open.** `Ctrl+P` (File → Open File…) searches the flat,
  gitignore-aware file list.
- **Drag to chat.** Drag any tree row or search result into the session pane to
  insert an `@relative/path` mention at the composer caret (directories keep a
  trailing `/`, paths with spaces are quoted). A drop anywhere on the session
  pane becomes a mention request; a cross-project drop is refused with a hint,
  and the app-level guard stops an external OS file drop from navigating the
  window.

### Editor tabs

- **A real editor, sized for this app.** CodeMirror 6 with syntax highlighting
  for the bundled language set, indentation, selection, undo/redo, search and a
  language badge on the tab. No Monaco, no LSP, no extension marketplace.
- **A second tab row.** File tabs live in their own strip directly under the
  session strip, rendered only while a file is open, and share one active tab
  with the main view. A dirty file shows a dot; a session tab keeps its status
  dot and a web tab its globe, so the kinds are distinguishable without clicking.
- **Save and format.** `Ctrl/Cmd+S` saves; Format Document uses the document's
  language and `.editorconfig`. External formatter commands are opt-in, read
  from validated prefs in main, run with `shell: false`, a 10 s timeout and
  output caps.
- **Safety.** Paths are project-relative POSIX strings; main re-resolves the
  project against the open-tab allowlist and applies a lexical + realpath
  containment check before every operation. Reads cap at 5 MB, editable writes
  and backups at 2 MB; larger, binary or UTF-16 files open read-only. A write
  carries the mtime the editor loaded, so a concurrent agent edit becomes a
  `conflict` result instead of being overwritten. `.git` is never written.
- **Recovery.** Dirty buffers are debounced to
  `<userData>/editor-backups/<tabId>.json`; a backup that differs from disk is
  restored as dirty after a crash or reload, and closing a dirty tab prompts
  Save / Discard / Cancel.
- **No reload storm.** A tab-table publish no longer remounts the editor or
  re-reads the file, so undo history, cursor and scroll survive window switches
  and Alt+Tab.

### Tabs and sessions

- **Unlimited tab records.** Session, Office, web and editor tabs are no longer
  capped at eight. What is bounded is _live hosts_ (below), not tabs; a closed
  tab is a resumable JSONL record.
- **Pinning.** Pinned tabs stay at the front, hide their close button, survive a
  relaunch and are skipped by Close All/Close Others.
- **Kind-scoped actions.** Close All/Close Others only touch their own kind, so
  closing all sessions leaves editor, web and Office tabs open.
- **One menu, two ways in.** The tab context menu and the `…` button expose the
  same actions; editor tabs add Copy Path and Copy Relative Path.
- **Wheel-scrollable strips.** Both rows scroll horizontally with the mouse
  wheel, reveal the active tab on selection, and keep a manual scroll position
  across window focus and tab status updates.
- **Project-scoped cleanup.** Removing a project closes every tab in that folder
  (including pinned tabs) after a dirty-editor prompt, without deleting the
  folder or Pi session files.

### Projects

- **New default project.** One click creates a dated folder
  (`YYYY-MM-DDTHH-mm-ss`, suffixed on collision) inside
  `<OS Documents>/Pi-Desktop`, registers it, makes it active and opens a
  session. The `Pi-Desktop` directory is created once and reused; no `git init`
  runs.
- The sidebar's project group lists session-row tabs only; file tabs stay in the
  editor row.

### Memory, hosting and reliability

- **A memory-derived live-host budget.** `liveHostBudget(totalMemory)` reserves
  20 % of physical RAM at 512 MB per host, clamped to 2–8; the process ceiling
  is `target + 2` (4–10). Before a spawn the least-recently-used **idle** host
  is parked, and a 30-second tick parks idle hosts when the app is over target
  or over 50 % of physical RAM. A busy session never blocks a new one.
- **The active tab is no longer exempt from the RSS guardrail.** A host over the
  1 GB threshold is stopped and resumed from JSONL when idle; streaming turns
  and long tool calls are never interrupted (the reaper asks `state.get` first).
- **Idle sleeping is on by default** (15 minutes for inactive tabs). The control
  host, Office host and bridge owner stay protected.
- **Bounded live renderers and caches.** Unlimited web tabs are URL records; at
  most four `WebContentsView`s stay live, and an evicted view reloads on
  activation. The renderer keeps at most four hydrated transcripts and a bounded
  blob cache, and a closed tab loses all of its caches immediately.
- **Host lifetime.** A service host exits when its stdin pipe closes, so an
  `electron-vite` dev restart (which kills main) no longer leaves invisible
  hosts behind; a failed start/restart terminates the child it spawned.
- **Diagnostics** reports `live/target (ceiling)`, aggregate host RSS/limit,
  system free/total memory and live web views, with over-target/over-memory
  badges.
- **No more stuck modals.** The Radix `pointer-events` lock is now a singleton:
  `package.json` overrides pin the stateful packages and an architecture test
  fails if a nested copy reappears. Creating and deleting a file no longer
  leaves every click swallowed.

### Updates

- **No full-width update banner.** An available release shows a compact status
  bar chip (**Update vX** → **Updating N%** → **Restart to update**); up to date,
  no-feed and error states live in **Settings → About & updates**.
- **Honest local builds.** `afterPack` writes `resources/build-info.json` with
  `channel: local|release`, the version, the short commit and `builtAt`. Local,
  dev, offline and safe-mode launches never auto-check; a manual check reports
  “No published release was found for this build” instead of an error.
- **Dismissal is per version** and a new version re-notifies.

### Packaging

- Installers still carry **one** Node runtime: `afterPack` prunes
  `resources/runtime/node` to the platform/arch being packaged, so a tree that
  holds Linux runtimes still builds a clean Windows installer and each package
  ships only its own runtime.

## Known limitations

Everything below is a real, user-visible limitation of v0.4.0, not a claim that
the feature is missing. The automated suite covers the logic; the items marked
“unverified on a real machine” need hardware/providers the build host does not
have.

### Platform and distribution

- **Unsigned builds.** SmartScreen/Gatekeeper warnings on first launch; signing
  and notarization are deferred ([backlog](/product/backlog/)).
- **macOS and Linux are beta.** macOS was not built for this release: it needs a
  Mac for a meaningful `.dmg`/`.zip`. The Linux AppImage and `.deb` for x64 and
  arm64 were built in WSL2 (Ubuntu) and verified structurally (deb metadata and
  file list, one bundled runtime per architecture, the packaged host bundle, the
  `.desktop` entry, and the AppImage ELF header and size). They have still not
  been installed or run on a real Linux desktop, and the arm64 binaries cannot be
  executed on the x64 build host.
- **The Windows installer builds, but has not been installed on a clean VM.**
  `package:win` produces both artefacts with URL-safe, target-distinct names; the
  clean-VM install and first session remain the manual acceptance gate.
- **The updater was not exercised against a live feed.** This build published no
  GitHub Release, so no download → restart → install round trip happened.

### Verified structurally, not on a live machine

- **Provider sign-in** (OAuth device/code flows) against real providers; the
  request/response plumbing and redaction are unit-tested.
- **Extension UI fidelity**: a real extension's `notify`/`status`/`widget`,
  `ctx.ui.custom()` overlays, footers/headers/custom editors and custom
  `renderCall`/`renderResult` renderers in the packaged app.
- **Office**: the wizard acceptance row (detect → install → sideload → verify)
  and the bridge end to end (a real pane attached, `document:"active"` following
  focus, `#name` routing). Automated tests use scripted `/health` and fake
  runners.
- **Plannotator review round trip** and the in-app web tab.
- **Web-tab isolation on a loaded page**: creation flags are asserted, not a real
  page proving `window.pi` is absent.
- **Editor and explorer against a real disk**: the workspace layer is tested with
  temporary directories and an in-memory editor, but the conflict path against a
  concurrently editing agent, hot-exit recovery across a real crash, and
  external-command formatters on each OS are not walked end to end.
- **Reliability**: crash/timeout banners against a real wedged host, safe mode
  against a genuinely broken extension, and the diagnostics bundle from a real
  run with real credentials.
- **Performance**: 60 fps is asserted structurally, and the RSS/restart budgets
  use injected samples; the host-budget policy is unit-tested but the 30-second
  reaper has not been observed under a real multi-gigabyte session.
- **The session surface against a live model**: the reducer, hydration, tool
  pairing and command paths are fixture-tested; a full live session with every
  new command has not been walked end to end since the chrome rewrite.
- **Drag, wheel and zoom feel**: splitter, sidebar, tab-strip and textarea
  gestures are pointer-tested in jsdom, not measured on a real display or
  trackpad.

### Upstream (not fixable in this app)

- **Pi's own writers are not crash-atomic.** `SettingsManager` writes
  `settings.json` with `writeFileSync`, and `SessionManager` appends/rewrites
  session JSONL with `appendFileSync`/`writeFileSync`. The app cannot patch the
  pinned SDK, so a crash _during Pi's own flush_ can still truncate those files.
  The app's own profile writes are atomic and `fsync` before the rename.
- **MCP is parity, not a built-in.** Like terminal Pi, MCP is reached through an
  installed extension; there is no first-party bridge
  ([backlog](/product/backlog/)).
- **Backups cover `settings.json`**, not every profile file. `models.json`,
  `keybindings.json` and imported themes are written atomically but are not
  backed up before the first app write.
- **Phase G (update channels) is deferred.** The app updates its own code only;
  the Pi runtime and installed extensions have no update channel yet.
- **No content search in the explorer.** Search matches names and paths, not
  file contents; there is no regex and no result paging.

### Deliberately deferred

See [`../product/backlog.md`](/product/backlog/) for the full list with
reasons: in-app terminal tab, native Plan/Review workspace, SQLite session
index/search, i18n, git worktrees, first-party MCP bridge, multi-window/scheduled
tasks/cloud sessions, code signing, and the external-editor launcher.

## Data, privacy and updates

- The app shares `~/.pi/agent` by default (settings, `auth.json`, sessions,
  extensions, packages). The onboarding profile step can keep a private profile
  under `userData` instead; the choice applies on the next launch.
- **Telemetry is off unless explicitly enabled.** The app sets
  `PI_TELEMETRY=0` for every host unless the preference is on, and never rewrites
  the shared `settings.json` for it.
- `auth.json` is Pi's and written `0600`; no IPC channel returns credential
  material, and the diagnostics bundle is redacted.
- Writes to the profile go through Pi's SDK managers or the app's atomic helpers
  (temp file → `fsync` → rename). A malformed `settings.json`, `auth.json` or
  `app-state.json` is reported and left untouched, never repaired silently.
- Editor hot-exit backups live under `<userData>/editor-backups` and are written
  atomically; they never enter the project folder.
- `@dieulc/checkpoints` keeps its own version line; installing it in terminal Pi
  reads the same shadow checkpoints the app writes.
